## 项目目标 (Goal)

把 spec 描述的 Echo v0.1 (跨云盘资源池控制面) 从设计文档落成可发布的单 Go 二进制 + Docker 镜像,与 `xmm2022/openlist-guangyapan-src` sidecar 通过 HTTP 协作,完成 ingest / restore / 最小后台。

## 架构 (Architecture, 来自 spec §2)

- 双进程: Echo (`:8080`) 控制面 + OpenList sidecar (`:5244`) 执行面
- Echo 自身: HTTP API + Web UI + Job runner + SQLite + sidecar HTTP client + .echo 输出
- 进程边界即接口契约;Echo 不通过 Go module import sidecar (spec §2 / §12 已否决)

## Tech stack

- Go 1.22+
- HTTP: `chi` v5
- 模板: `templ` + htmx (vendor)
- 日志: `log/slog`
- DB 访问: `sqlc`
- 迁移: `golang-migrate`
- DB: SQLite (v0.1, 仅此一个)。**驱动锁定 `modernc.org/sqlite` (纯 Go,scratch 友好)**;不用 `mattn/go-sqlite3` (CGO + scratch 难维护)。

## 3. Phase 2 — sidecarclient (HTTP client)

Echo 调 sidecar 的唯一通道。隔离 HTTP 细节,业务层只看 `Sidecar` interface。

任务:
- `internal/sidecarclient/client.go`:
  - `New(cfg Config) *Client` (`base_url`、auth token 来源 env、`request_timeout`、`stream_timeout`)
  - 公共 request helper: 注入 `Authorization: Bearer <token>`、设超时;**不做自动重试** (spec §5 "不做的")
  - 版本探测: `Version(ctx) (string, error)` 调 `GET /api/public/settings` 或 `GET /ping`,解出 commit/tag
  - **min_version 比较: 精确字符串相等**。配置字段 `min_version` 与 sidecar 返回的 commit/tag 必须严格相等,否则 `ErrSidecarVersionTooOld`。Echo release notes 钉死版本字符串。
  - **错误类型分层 (修订 R2)**:
    - `ErrSidecarUnreachable` — dial / DNS / TCP / TLS 失败、`context.DeadlineExceeded`、对端断流。**handler 映射 503**。
    - `SidecarHTTPError{StatusCode int, Method, URL string}` — HTTP 层非 2xx 响应 (含 5xx)。**handler 不直接映射**,业务层 (Phase 7 restore fallback) 视为 "本副本失败,试下一个",全部副本失败才进 `ErrAllCopiesDead → 404`。
    - `ErrCASRestoreFailed` — sidecar 4xx 拒绝 CAS restore (含非 .cas 后缀拦截);ingest item failed,**绝不 fallback**。
    - `ErrSidecarVersionTooOld` — 版本不匹配,readyz fail。
- `storage.go`: `ListStorages(ctx) ([]Storage, error)` 调 `GET /api/admin/storage/list`
- `putcas.go`:
  - `PutCAS(ctx, PutCASRequest) (*ItemResult, error)` 调 `PUT /api/fs/put`
  - **`req.CASName` 必须以 `.cas` 结尾**,否则在 client 入口直接返回 `ErrCASRestoreFailed` (不发 HTTP);fake sidecar 行为同步
  - `File-Path` header = `path.Join(req.RemoteDir, req.CASName)`
  - Body = `req.CASBody`;`req.ContentLength = req.CASSize` (已知 CASSize 时必须发 `Content-Length`,不按 chunked 描述/实现)
  - 返回值: sidecar JSON → `Status ∈ {restored, skipped_dup, failed}` + `CloudPath / SizeBytes / Hashes`
  - 200/201 成功;4xx → `ErrCASRestoreFailed`;5xx → `SidecarHTTPError{StatusCode}`;dial/超时 → `ErrSidecarUnreachable` (不重试)
- `link.go`: `Link(ctx, mount, remotePath) (*DirectLink, error)` 调 `POST /api/fs/link`
- `stream.go`:
  - `Stream(ctx, StreamRequest) (*StreamResult, error)` 调 `GET /d/<path>`
  - 透传 `req.Headers` 中 `Range / If-Range / If-Modified-Since / If-None-Match / User-Agent` 到上游
  - 把上游 200/206/304/416 + `Content-Length / Content-Range / Content-Type / Accept-Ranges / Last-Modified / ETag` 透传回 `StreamResult`;`Body` 是 `resp.Body`,handler 用完 Close

- fake sidecar harness `internal/sidecarclient/fakesidecar/` (导出供 Phase 5/7/11 复用):
  - `httptest.NewServer`,mock 各 endpoint 全分支 (200/404/410/5xx/timeout/版本字符串)
  - **PutCAS 拒绝非 `.cas` 后缀** (返回 4xx)
  - **Stream 实现 Range 正常 / 越界 416 / 304** (Phase 7 直接复用)
  - 单测覆盖每个 method × 各分支

## 5. Phase 4 — pathsafe + echofile output

把 spec §3 的硬规则落成可复用函数。Ingest pipeline / handler / producer ref: 解析都要复用。

任务:
- `internal/pathsafe/validate.go`:
  - `ValidateRelPath(rel string) error` 严格按 spec §3:
    - 空 → 拒
    - len > 4096 → 拒
    - 含 NUL / 任何 `< 0x20` 控制字符 → 拒
    - 含反斜杠分段 / Windows 盘符 (`C:` 等) → 拒
    - 任一分段为 `..` → 拒
    - 绝对路径 (`/` 前缀) → 拒
    - **`a//b` 允许** (filepath.Clean 后规范化为 `a/b`,再过一遍全套规则);**`./a` 允许** (Clean 后变 `a`);**Clean 后为 `.` / 空 / 含 `..` / 绝对路径 → 拒**
  - 表驱动单测,正反例至少各 12 条 (含 ` `、`a/../b`、`a/b/../c`、Windows 盘符样本、`/etc/passwd`、`a//b`、`./a`、`.` 等)
- `internal/pathsafe/safe_join.go` — **三个互不混用的 helper (修订 R2)**:

  **A. `ResolveExistingUnderRoot(root, candidate string) (final string, err error)`** — 校验已存在路径,**不创建任何东西**。`/api/ingest/manual` 的 `cas_tree_path` / `manifest_path` / producer `ref:` 都用它。
  - `root` 必须是绝对路径 + 已存在 + 是目录,否则拒
  - `candidate` 允许绝对或相对:
    - 绝对路径 → 直接使用
    - 相对路径 → `filepath.Join(root, candidate)`,join 前对 candidate 跑 `ValidateRelPath`
  - 路径必须**已存在** (`os.Lstat` 不 `ENOENT`),否则拒
  - lstat 显示是 symlink → 拒 (final 自身不允许是 symlink)
  - `evaluated, err := filepath.EvalSymlinks(final)` — err 非 nil 必拒
  - `rootEvaluated, err := filepath.EvalSymlinks(root)` — err 非 nil 必拒
  - `rel, err := filepath.Rel(rootEvaluated, evaluated)` — err 非 nil 必拒;`rel` 以 `..` 开头或等于 `..` → 拒
  - **不调用 MkdirAll**,**不调用任何写**
  - 返回值: `evaluated` (规范化后的真实路径)
  - 调用方还要根据上下文加约束: 比如 manifest_path 调用方再判 `mode.IsRegular()`;cas_tree_path 调用方再判 `mode.IsDir()`

  **B. `PrepareOutputUnderRoot(root, rel string, suffix string) (final string, err error)`** — `.echo` 写盘专用。需要创建 parent,但不创建 final。
  - `root` 必须是绝对路径 + 已存在 + 是目录,否则拒
  - `ValidateRelPath(rel)` 先过
  - `rootEvaluated, err := filepath.EvalSymlinks(root)`;err 非 nil 必拒;从 `rootEvaluated` 开始逐段处理 `filepath.Dir(rel + suffix)` 的每个 segment
  - 逐段安全创建 parent: 对下一段先 `os.Lstat(next)`;已存在且是 symlink → 立即拒;已存在且不是目录 → 拒;不存在则只在**当前已验证目录**下 `os.Mkdir(next, 0o755)`;不要对完整 parent 调 `MkdirAll`
  - 每创建/进入一段后可 `EvalSymlinks(next)` + `filepath.Rel(rootEvaluated, evaluated)` 复验仍在 root 内;任一 err 或 `rel2` 以 `..` 开头/等于 `..` → 拒
  - `final := filepath.Join(rootEvaluated, rel + suffix)`;`lstat(final)` 是 symlink → 拒 (但 final 不存在是允许的,这是输出路径);若 final 已存在且不是 regular file → 拒
  - `SafeJoinUnderLibrary(libRoot, rel)` = `PrepareOutputUnderRoot(libRoot, rel, ".echo")` (向后兼容包装)

  **C. `PrepareNewDirUnderRoot(root, rel string) (final string, err error)`** — producer job workdir 专用,创建一个新目录。
  - `root` 必须绝对 + 存在 + 目录
  - `ValidateRelPath(rel)`
  - `rootEvaluated, err := filepath.EvalSymlinks(root)`;err 非 nil 必拒;从 `rootEvaluated` 开始逐段处理 `filepath.Dir(rel)` 的每个 segment
  - parent 用与 B 相同的逐段安全创建规则: 遇 symlink 立即拒;不存在的段只在已验证父目录下 `os.Mkdir(next, 0o755)`;不要对完整 parent 调 `MkdirAll`
  - `final := filepath.Join(rootEvaluated, rel)`;**要求 `final` 当前不存在** (`os.Lstat` 必须 `ENOENT`),已存在 → 拒;若 final 自身任一路径段在检查时是 symlink → 拒
  - `os.Mkdir(final, 0o750)`,然后 `EvalSymlinks(final)` / `Rel(rootEvaluated, evaluated)` 复验仍在 root 内
  单测必须覆盖每个 helper:
  - root 不存在 / 是文件 / 相对路径 → A/B/C 全拒
  - parent / final 含 symlink 指向 root 外目录 → 全拒,且拒绝前不得在 root 外创建目录
  - A: 路径不存在 → 拒;B: parent 不存在 → 自动逐段安全创建;C: final 已存在 → 拒
  - rel 含 `..` 但 Clean 后仍在 root 内 → ValidateRelPath 已拒
  - **A 不调用 MkdirAll** (用 fs syscall hook 或临时受限目录验证)
- `internal/echofile/output.go`:
  - `PutAtomic(final string, payload []byte) error`: 写 `final + ".tmp"` → `f.Sync()` → `os.Rename(tmp, final)` → fsync 父目录
  - `RemoveTmp(libraryRoot string) ([]string, error)`: 启动 reconcile 用,递归找并删 `.echo.tmp`
- 单测:
  - PutAtomic 正常 + 故意不 rename 留 .tmp,验证 RemoveTmp 删
  - `pathsafe` 三 helper 全部反例

依赖: Phase 0

验收:
- `go test ./internal/pathsafe/... ./internal/echofile/...` 全绿
- `internal/pathsafe` line coverage ≥ 90%
- 所有 Phase 5/6/8/9 调用 fs / ref: / 用户传入路径之处都通过 `pathsafe.{ResolveExistingUnderRoot, PrepareOutputUnderRoot, PrepareNewDirUnderRoot}`,不允许直接 `filepath.Join` 拼用户输入,**不允许混用 helper** (PR review checklist)

## 6. Phase 5 — Ingest pipeline (核心业务,最重)

整合 Phase 1-4,落实 spec §4 manual import 全流程,含两段提交 + reconcile。

任务:
- `internal/ingest/pipeline.go`: `RunManual(ctx, job Job, deps Deps) error`,deps = `*store.Store / sidecar.Sidecar / *castree.Reader / Config`
- 主循环按 spec §4 步骤 1-4。**每 item 顺序固定为**:
  1. handler 入口已做的 `ValidateRelPath` 不算第二道,这里 (每 item) 再次 `ValidateRelPath(item.RelPath)` (spec §3 三道关之二)
  2. `resolveCandidateBlob` (在一个独立读事务,或并入段 1 起始)
  3. `writeBlobHashes` (同上,可与 candidate 解析共享只读快照)
  4. **`restoreWithSidecar`** — Status != restored/skipped_dup → item failed,跳到 5 之外的 failed_items 收集,**绝不**进段 1
  5. `applyTwoPhaseCommit` (段 1, BEGIN IMMEDIATE)
  6. `writeEchoFile` (段 2 + 段 3)
  对应 spec §4 步骤 3.a → 3.b → 3.c → 3.d。

子函数 (各自独立测):

**resolveCandidateBlob(tx, payload) (blobID int64, conflicts []HashConflict, err error)**
- 按每个 hash 查 `blob_hashes` (`hash_value_norm + size`)
- 命中数 0 → 新建 blob;命中 1 → 沿用;>1 → 取最老 + 写 `hash_conflicts(reason="hash_multi_blob")`
- **并发约束 (修订 R3)**: `resolveCandidateBlob + writeBlobHashes` 必须在一个短 `BEGIN IMMEDIATE` 事务内完成,或在 `blob_hashes` UNIQUE 冲突时重新查询冲突 hash 并切换到已存在 owner。实现目标是同 hash 多 worker 并发 ingest 不触发外泄 UNIQUE 错误,最终按 `hash_owned_by_other_blob` / 幂等规则收敛。

**writeBlobHashes(tx, blobID, payload) ([]HashConflict, error)**
- 逐 hash 走 spec §4 步骤 3.b "未存在 INSERT / 已存在且 owner=candidate 幂等 / 已存在且 owner!=candidate → `hash_conflicts(reason="hash_owned_by_other_blob")` 不写 INSERT"
- 如果采用 UNIQUE 冲突重试路线: 捕获 `blob_hashes(hash_type, hash_value_norm, size)` UNIQUE 后,必须在同一 item 流程内重新 `SELECT blob_id`,再按 owner 是否等于 candidate 处理;不得把该冲突当 job/item error。

**restoreWithSidecar(ctx, item, target_subdir) (*ItemResult, terminated bool, err error)** (spec §4 步骤 3.c, **修订 R2 BLOCKER**):
- **入口校验** (远端路径不做 symlink 解析,但仍要 sanitize,spec §3 "远端路径...仍跑 validateRelPath"):
  - `pathsafe.ValidateRelPath(target_subdir)` — 拒 `..` / 绝对路径 / 控制字符
  - `pathsafe.ValidateRelPath(item.RelPath)` (handler 已查过,这里第二道,spec §3 三道关之 "每 item")
- **找 .cas 字节流**: `castree.LocateCASFile(treeRoot, item.RelPath)` → 本地路径;`os.Open` 拿 `io.ReadCloser`,`stat.Size()` 拿 `CASSize`
- **构造 PutCASRequest** (spec §2 核心 interface + §4 步骤 3.c):
  - `StorageMount = account.storage_mount`
  - `RemoteDir = "/" + path.Join(target_subdir, path.Dir(item.RelPath))` (远端绝对路径,sidecar storage 内的)
  - `CASName = path.Base(item.RelPath) + ".cas"` (Phase 2 client 入口会再校验 .cas 后缀)
  - `CASBody = casFile`,`CASSize = stat.Size()`
- 调 `sidecar.PutCAS(ctx, req)` → `*ItemResult`
- **`remotePath` 定义 (修订 R3)**: `applyTwoPhaseCommit` 的 `(sidecar_id, storage_mount, remote_path)` key 必须使用 storage 内最终文件绝对路径。优先取 `result.CloudPath`;若 sidecar 未返回,则 derive 为 `path.Join(req.RemoteDir, strings.TrimSuffix(req.CASName, ".cas"))`。禁止把 `.cas` 路径、目录路径、或本地 cas_tree 路径写入 `file_copies.remote_path`。
- **结果分支** (spec §4 步骤 3.c):
  - `Status="restored"` → 返回 `(result, terminated=false, nil)`,调用方进段 1 (`applyTwoPhaseCommit`)
  - `Status="skipped_dup"` → 同 restored,**不**记 warning (目标已存在),进段 1 (段 1 内会再判 blob_id 一致性,详见 spec §4 步骤 3.d skipped_dup 同样适用)
  - `Status="failed"` → **返回 `(nil, terminated=true, nil)`**;调用方:
    - **不写 file_copies / 不写 .echo / 不更新 echo_written**
    - `job.warnings += 1`,item 进 `failed_items[]`
    - **不调用任何其他 sidecar method** (硬约束,反 fallback,spec §5 / §4 关键决策)
  - `err != nil` 且 `errors.Is(err, sidecarclient.ErrSidecarUnreachable)` → 返回错误,job 整体降级到 503/失败 (spec §5)
  - 其他 err (`ErrCASRestoreFailed` / `SidecarHTTPError`) → item failed (同 Status=failed 路径)

**applyTwoPhaseCommit (段 1, 必须 BEGIN IMMEDIATE)** (spec §4 步骤 3.d):
```
BEGIN IMMEDIATE;
  SELECT id, blob_id FROM file_copies
   WHERE sidecar_id=? AND storage_mount=? AND remote_path=?;
  -- 同事务内,SQLite 串行化保证 TOCTOU 不存在
  IF row 存在 AND row.blob_id != candidate_blob:
      INSERT hash_conflicts(reason='copy_blob_mismatch', ...);
      COMMIT; return terminated=true;
  IF row 存在 AND row.blob_id == candidate_blob:
      UPDATE file_copies SET status='live', last_seen=?,
             cloud_file_id=COALESCE(?, cloud_file_id),
             pickcode=COALESCE(?, pickcode)
       WHERE id=row.id;          -- blob_id 列不在 SET 里
  IF row 不存在:
      INSERT INTO file_copies (..., blob_id=candidate_blob, status='live', ...);
  UPSERT library_entries(library_id, rel_path) DO UPDATE
      SET name=excluded.name, blob_id=excluded.blob_id, echo_written=0;
COMMIT;
```
**关键:整个段 1 必须在 `BEGIN IMMEDIATE` 事务内**,SQLite WAL 下 `BEGIN IMMEDIATE` 立刻获取 RESERVED 锁,后续 worker 串行,杜绝 TOCTOU。skipped_dup 走同一分支判定 (spec §4: "skipped_dup 同样适用")。

**writeEchoFile (段 2 + 段 3)**:
- 段 2 (fs): `pathsafe.SafeJoinUnderLibrary` → `castree.Payload.Encode` → `echofile.PutAtomic`
- 段 3 (单语句 SQL,**不**在段 1 事务里): `UPDATE library_entries SET echo_written=1 WHERE id=?`

子模块:
- `internal/ingest/dedup.go`: dedup key = `(library_id, rel_path, account_id, storage_mount, target_remote_dir, basename)`,内存 set,job 内查重,不持久化
- `internal/ingest/reconcile.go`: 启动时一次,按 spec §3 写盘时机 4 条:
  - `echo_written=0` 且本地 .echo 不存在 → 重写 + `echo_written=1`
  - `echo_written=0` 且本地 .echo 存在 → **校验通过定义: 解码现有 .echo,Payload.size 与 DB blob.size 一致 + 已知 blob_hashes 全部能在 .echo payload 字段中找到对应值且相等**;不重算原始文件 sha1 (本地只有占位,无字节流);失败则重写,成功置 `echo_written=1`
  - 残留 `.echo.tmp` → 删
  - 孤儿本地 .echo (无对应 live row) → slog warning,**不删**
- 失败项收集: `jobs.progress` JSON 含 `failed_items: [{rel_path, reason}]`,1s 节流写库

测试 (mock sidecar + 真 SQLite):

- **并发 conflict 校验**: 两 worker 对同一 `(sidecar_id, storage_mount, remote_path)` 同时写不同 candidate_blob,断言只有一个写成功 + 另一个写 `copy_blob_mismatch` + 只有一个 live copy

## 16. 已拍板的工程决策 (review 应用结果)

### R1 (第一轮 codex review) — 8 条开放问题拍板,不再回头:

1. **段 1 UPSERT 原子性** → 必须 `BEGIN IMMEDIATE` 事务包整个 "SELECT existing → 分支 → INSERT/UPDATE → UPSERT library_entries → COMMIT";SQLite WAL 下 RESERVED 锁立刻持有,杜绝 TOCTOU。详见 Phase 5 `applyTwoPhaseCommit`。
2. **PutCAS .cas 后缀识别** → `CASName` 必须 `.cas` 结尾,client 入口校验失败直接返回 `ErrCASRestoreFailed`;fake sidecar 同步拒绝非 .cas;真 sidecar 行为放 integration 验证。详见 Phase 2。
3. **min_version 比较策略** → 精确字符串相等。配置 `min_version` 与 sidecar 返回的 commit/tag 必须 ==,否则 `ErrSidecarVersionTooOld`;Echo release notes 钉死字符串。详见 Phase 2。
4. **ValidateRelPath 处理 `a//b`** → 允许;`filepath.Clean` 后规范化为 `a/b`;Clean 后再过一遍全套规则;Clean 后为 `.` / 空 / 含 `..` / 绝对路径仍拒。`./a` 规范化为 `a` 通过。详见 Phase 4。
5. **reconcile 校验 hash 定义** → 解码现有 .echo,Payload.size 与 DB blob.size 一致 + 已知 blob_hashes 在 .echo payload 字段中找到对应值且相等;**不重算原始文件 sha1** (本地只有占位 payload,无字节流)。失败重写,成功置 `echo_written=1`。详见 Phase 5 reconcile。
6. **fake sidecar Range 边界** → Phase 2 的 fake sidecar 直接实现 Range 正常 / 416 / 304;Phase 7 单测验证透传;Phase 11 只做端到端复验。详见 Phase 2。
7. **SQLite 驱动选型** → **`modernc.org/sqlite` (纯 Go)**,scratch 镜像友好;不用 `mattn/go-sqlite3` (CGO + scratch 难维护)。Phase 0 go.mod 锁定。
8. **htmx 来源** → vendor `htmx.min.js` 到 `internal/web/static/`,README 记录版本和来源;**不使用 CDN**。详见 Phase 9。
