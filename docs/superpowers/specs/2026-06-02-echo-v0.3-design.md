# Echo v0.3 设计

- 日期: 2026-06-02
- 作者: Echo 项目
- 状态: 设计稿,待用户 review
- 范围: 只设计 v0.3;不写实现代码

## 1. 项目定位

Echo v0.3 是建在 v0.1 资源池和 v0.2 Emby 播放代理之上的 NextFind-like 自动订阅层。

一句话: **Echo 订阅 TMDB 媒体条目,从 Telegram channel 与 poster source 发现资源,用规则引擎评分,再把被接受的 115 分享排成现有 `ingest_producer` job,最终仍由 `115share2cas` + v0.1 ingest pipeline 入库。**

v0.3 是应用层,不是新的云盘执行面。它不生成 CAS payload,不直接转存云盘,不写 `library_entries` / `file_copies`,不 import OpenList sidecar Go 包。

### 设计审查记录

本 spec 的主要段落均经过子代理 focused review,审查意见已合并:

- 架构方向: Epicurus
- 数据模型 / 数据流: Popper
- 错误处理 / 安全边界: Plato
- 组件 / API: Lovelace
- 测试 / release gate: Euclid

### v0.3 目标

包含:

- TMDB 订阅: 按 `tmdb_id + media_type` 创建订阅,缓存 TMDB details/search 结果。
- Telegram MTProto source: 使用已有 session file 的 `ref:` 引用,抓取配置 channel 的历史与增量消息。
- Poster HTTP source: 至少一个 poster 站 adapter,通过安全 HTTP client 抓取并解析候选资源。
- 规则评分: 解析分辨率、HDR/色彩、音轨、体积、扩展名、组名和自定义关键词,产出 deterministic score snapshot。
- 资源决策: 候选资源匹配订阅后生成 `subscription_matches`,支持 accept/reject/retry。
- Producer dispatch: 对 accepted 115 资源生成现有 `ingest_producer` job,复用 `115share2cas` 和 v0.1 ingest。
- Discovery scheduler: source crawl、subscription check、dispatch、reconcile、TMDB refresh 的持久化调度状态。
- 管理 API/UI: 管理订阅、sources、producer profiles、rule profiles、candidates、matches、runs。
- 安全边界: 统一 secret refs、admin-only discovery routes、SSRF 防护、redaction、raw debug 限制。
- 测试与 release gate: fake source full path + 小规模真实 Telegram/115 gate。

不包含:

- Telegram 登录、验证码、2FA 创建 session 流程。v0.3 release gate 只读取已有 session file ref。
- 真实 115 SDK 直接转存。
- 139 / 189pc 自动订阅 producer。它们仍可通过 v0.1 manual import / 已有 CAS tree 入库。
- 全量 TMDB seed / trending 大库。
- 完整海报墙前端。v0.3 UI 是管理面,不是媒体浏览产品。
- Emby 媒体库质量扫描。v0.3 baseline 来自自己成功入库的 match/history。
- 普通用户自助订阅权限。v0.3 discovery 管理面 admin-only。

## 3. 架构

v0.3 采用 **Echo 内置 discovery 应用层**。

已评估并否决:

- 独立 discovery sidecar: 进程边界干净,但引入额外部署、认证、配置与 release gate。
- NextFind bridge: 验证快,但 clean-room、凭据边界和长期维护都差。

整体流向:

```text
TMDB subscription
    |
    v
discovery scheduler
    |
    +--> Telegram MTProto source ----+
    +--> Poster HTTP source ---------+--> normalize candidates
                                      |
                                      v
                                  rules score
                                      |
                                      v
                             subscription_matches
                                      |
                                  accepted
                                      |
                                      v
                           ingest_producer job
                                      |
                                      v
                    115share2cas -> CAS tree -> v0.1 ingest
                                      |
                                      v
                      library_entries / file_copies / .echo
```

Discovery stops at normalized candidates and dispatch decisions. The only path that creates library entries or copies remains v0.1 ingest.

## 4. Provider 范围

Echo core remains multi-cloud:

- v0.1/v0.2 still support 115 / 139 / 189pc CAS ingest, restore, and stream boundaries.
- v0.3 discovery schema remains provider-neutral.

v0.3 automatic dispatch release gate is **115-only**:

- Supported dispatch provider: `provider='115'`
- Supported producer tool: `115share2cas`
- Non-115 candidates may be stored as `unsupported_provider` or `review`, but must never be auto-queued.

139 / 189pc automatic subscription requires a separate design because current Echo has no auto-exec producer contract equivalent to `115share2cas` for those providers.

Dependency boundary:

- Final dependency pinning and license verification happen in the implementation plan before code changes.

## 6. 数据模型

SQLite remains the only committed database.

### `tmdb_media`

TMDB cache and local search base for subscribed items.

```sql
CREATE TABLE tmdb_media (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  tmdb_id         TEXT NOT NULL,
  media_type      TEXT NOT NULL CHECK (media_type IN ('movie','tv')),
  language        TEXT NOT NULL,
  title           TEXT NOT NULL,
  original_title  TEXT,
  release_year    INTEGER,
  poster_path     TEXT,
  status          TEXT,
  raw_json        TEXT NOT NULL,
  fetched_at      INTEGER NOT NULL,
  next_refresh_at INTEGER NOT NULL,
  last_error_kind TEXT,
  last_error_message TEXT,
  UNIQUE (tmdb_id, media_type, language)
);
```

### `discovery_sources`

Configured discovery sources.

```sql
CREATE TABLE discovery_sources (
  id                 INTEGER PRIMARY KEY AUTOINCREMENT,
  kind               TEXT NOT NULL CHECK (kind IN ('telegram_mtproto','poster_http','manual')),
  name               TEXT NOT NULL,
  enabled            INTEGER NOT NULL DEFAULT 1,
  config_json        TEXT NOT NULL,
  secret_ref         TEXT,
  rate_limit_json    TEXT,
  scheduler_state    TEXT NOT NULL DEFAULT 'healthy'
    CHECK (scheduler_state IN ('healthy','backoff','disabled','auth_failed','unhealthy')),
  next_run_at        INTEGER,
  locked_until       INTEGER,
  backoff_until      INTEGER,
  failure_count      INTEGER NOT NULL DEFAULT 0,
  last_success_at    INTEGER,
  last_error_kind    TEXT,
  last_error_message TEXT,
  created_at         INTEGER NOT NULL,
  updated_at         INTEGER NOT NULL
);
```

Sensitive fields in `config_json` are forbidden. Secrets use `secret_ref` and `internal/secrets`.

### `telegram_channels`

Per-channel configuration and cursor state.

```sql
CREATE TABLE telegram_channels (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  source_id           INTEGER NOT NULL REFERENCES discovery_sources(id) ON DELETE CASCADE,
  channel_ref         TEXT NOT NULL,
  stable_peer_id      TEXT,
  username_snapshot   TEXT,
  title_snapshot      TEXT,
  level_flags         INTEGER NOT NULL DEFAULT 0,
  enabled             INTEGER NOT NULL DEFAULT 1,
  last_message_id     INTEGER,
  last_message_date   INTEGER,
  next_run_at         INTEGER,
  locked_until        INTEGER,
  backoff_until       INTEGER,
  failure_count       INTEGER NOT NULL DEFAULT 0,
  last_error_kind     TEXT,
  last_error_message  TEXT,
  created_at          INTEGER NOT NULL,
  updated_at          INTEGER NOT NULL,
  UNIQUE (source_id, channel_ref)
);
```

FloodWait can be source/session-level or channel-level. The scheduler must respect the stricter active backoff.

### `discovery_producer_profiles`

Safe default producer dispatch configuration.

```sql
CREATE TABLE discovery_producer_profiles (
  id                 INTEGER PRIMARY KEY AUTOINCREMENT,
  name               TEXT NOT NULL UNIQUE,
  provider           TEXT NOT NULL,
  tool               TEXT NOT NULL,
  target_account     TEXT NOT NULL REFERENCES accounts(id),
  target_subdir_template TEXT NOT NULL DEFAULT '',
  library_rel_path_template TEXT NOT NULL DEFAULT '',
  default_args_json  TEXT NOT NULL,
  enabled            INTEGER NOT NULL DEFAULT 1,
  created_at         INTEGER NOT NULL,
  updated_at         INTEGER NOT NULL,
  CHECK (provider = '115'),
  CHECK (tool = '115share2cas')
);
```

`default_args_json` may include `cookie_file` and `recycle_password_file`, but only as `ref:` values. It must pass the same producer validation path used by HTTP ingest.

### `rule_profiles`

Versioned scoring configuration.

```sql
CREATE TABLE rule_profiles (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  name           TEXT NOT NULL UNIQUE,
  version        INTEGER NOT NULL DEFAULT 1,
  rules_json     TEXT NOT NULL,
  enabled        INTEGER NOT NULL DEFAULT 1,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL
);
```

v0.3 stores rules as JSON rather than normalized tables. The rule engine validates the JSON shape before saving and stores the rule profile version on every match.

### `discovery_subscriptions`

Admin-created TMDB subscriptions.

```sql
CREATE TABLE discovery_subscriptions (
  id                       INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id                 TEXT NOT NULL REFERENCES users(id),
  tmdb_id                  TEXT NOT NULL,
  media_type               TEXT NOT NULL CHECK (media_type IN ('movie','tv')),
  tmdb_language            TEXT NOT NULL DEFAULT 'zh-CN',
  title_snapshot           TEXT NOT NULL,
  library_id               INTEGER NOT NULL REFERENCES libraries(id),
  producer_profile_id      INTEGER NOT NULL REFERENCES discovery_producer_profiles(id),
  rule_profile_id          INTEGER NOT NULL REFERENCES rule_profiles(id),
  status                   TEXT NOT NULL DEFAULT 'active'
    CHECK (status IN ('active','paused','completed','disabled')),
  season_filter_json       TEXT,
  current_best_match_id    INTEGER,
  current_best_score_json  TEXT,
  next_check_at            INTEGER,
  locked_until             INTEGER,
  last_checked_at          INTEGER,
  failure_count            INTEGER NOT NULL DEFAULT 0,
  last_error_kind          TEXT,
  last_error_message       TEXT,
  created_at               INTEGER NOT NULL,
  updated_at               INTEGER NOT NULL,
  UNIQUE (tmdb_id, media_type, owner_id, library_id)
);
```

`current_best_*` fields are denormalized cache only. The source of truth is successful `subscription_matches`.

For TV, `season_filter_json` and match episode fields provide v0.3's first season/episode granularity. Full episode ignore/extra management is not in v0.3.

### `discovered_resources`

Normalized candidates from sources.

```sql
CREATE TABLE discovered_resources (
  id                 INTEGER PRIMARY KEY AUTOINCREMENT,
  source_id          INTEGER NOT NULL REFERENCES discovery_sources(id),
  provider           TEXT NOT NULL,
  link_kind          TEXT NOT NULL CHECK (link_kind IN ('115_share','unknown')),
  external_key       TEXT NOT NULL,
  tmdb_id            TEXT,
  media_type         TEXT CHECK (media_type IS NULL OR media_type IN ('movie','tv')),
  title              TEXT,
  season_number      INTEGER,
  episode_start      INTEGER,
  episode_end        INTEGER,
  share_code         TEXT,
  receive_code       TEXT,
  share_url_redacted TEXT,
  raw_text_redacted  TEXT,
  raw_text_ref       TEXT,
  parsed_json        TEXT NOT NULL,
  feature_json       TEXT NOT NULL,
  status             TEXT NOT NULL DEFAULT 'candidate'
    CHECK (status IN ('candidate','review','rejected','unsupported_provider','accepted','queued','imported','failed')),
  first_seen_at      INTEGER NOT NULL,
  last_seen_at       INTEGER NOT NULL,
  UNIQUE (source_id, external_key)
);
```

`receive_code` and `share_code` are sensitive resource metadata. They are never logged and are redacted in list responses. Raw text storage is capped and may be disabled by config.

### `subscription_matches`

Durable decision ledger.

```sql
CREATE TABLE subscription_matches (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  subscription_id      INTEGER NOT NULL REFERENCES discovery_subscriptions(id) ON DELETE CASCADE,
  resource_id          INTEGER NOT NULL REFERENCES discovered_resources(id) ON DELETE CASCADE,
  rule_profile_id      INTEGER NOT NULL REFERENCES rule_profiles(id),
  rule_profile_version INTEGER NOT NULL,
  season_number        INTEGER,
  episode_start        INTEGER,
  episode_end          INTEGER,
  score_json           TEXT NOT NULL,
  previous_score_json  TEXT,
  decision             TEXT NOT NULL
    CHECK (decision IN ('reject','review','accept','queue','imported','failed')),
  reason               TEXT NOT NULL,
  dispatch_state       TEXT NOT NULL DEFAULT 'none'
    CHECK (dispatch_state IN ('none','queued','running','succeeded','failed')),
  idempotency_key      TEXT NOT NULL UNIQUE,
  queued_job_id        INTEGER REFERENCES jobs(id),
  result_library_entry_id INTEGER REFERENCES library_entries(id),
  result_blob_id       INTEGER REFERENCES blobs(id),
  result_copy_id       INTEGER REFERENCES file_copies(id),
  failure_kind         TEXT,
  failure_message      TEXT,
  created_at           INTEGER NOT NULL,
  updated_at           INTEGER NOT NULL,
  decided_at           INTEGER,
  finished_at          INTEGER
);
```

Duplicate accept prevention is enforced by the `idempotency_key` unique constraint inside a store transaction, not by the generic job runner.

### `discovery_runs`

Audit table for scheduler and manual run endpoints.

```sql
CREATE TABLE discovery_runs (
  id                INTEGER PRIMARY KEY AUTOINCREMENT,
  kind              TEXT NOT NULL CHECK (kind IN ('source_crawl','subscription_check','dispatch','reconcile','tmdb_refresh')),
  source_id         INTEGER REFERENCES discovery_sources(id),
  subscription_id   INTEGER REFERENCES discovery_subscriptions(id),
  job_id            INTEGER REFERENCES jobs(id),
  status            TEXT NOT NULL CHECK (status IN ('pending','running','succeeded','failed','canceled')),
  counters_json     TEXT NOT NULL DEFAULT '{}',
  error_kind        TEXT,
  error_message     TEXT,
  started_at        INTEGER,
  finished_at       INTEGER,
  created_at        INTEGER NOT NULL
);
```

### `discovery_raw_access_events`

Raw discovery data access audit trail.

```sql
CREATE TABLE discovery_raw_access_events (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  resource_id    INTEGER NOT NULL REFERENCES discovered_resources(id) ON DELETE CASCADE,
  actor_user_id  TEXT NOT NULL REFERENCES users(id),
  request_id     TEXT,
  response_bytes INTEGER NOT NULL,
  redacted        INTEGER NOT NULL DEFAULT 1,
  accessed_at     INTEGER NOT NULL
);
```

Required indexes:

- due sources: `(enabled, scheduler_state, next_run_at, locked_until)`
- due channels: `(source_id, enabled, next_run_at, locked_until)`
- due subscriptions: `(status, next_check_at, locked_until)`
- candidates by TMDB: `(tmdb_id, media_type, status, last_seen_at DESC)`
- matches by subscription/status: `(subscription_id, decision, dispatch_state, updated_at DESC)`
- queued job lookup: `(queued_job_id)`
- raw access audit: `(resource_id, accessed_at DESC)`

## 7. Job 与 scheduler

New job kinds:

- `discovery_source_crawl`
- `discovery_subscription_check`
- `discovery_dispatch`
- `discovery_reconcile`
- `discovery_tmdb_refresh`

`cmd/echo/main.go` must compose handlers:

```text
handlers := merge(
  job.IngestHandlers(...),
  discovery.JobHandlers(...),
)
```

Discovery cannot rely on the generic `jobs` table for scheduling semantics. It must maintain app-level leases and uniqueness:

- `locked_until` prevents overlapping source/subscription work.
- `backoff_until` handles FloodWait, TMDB outage, and poster temporary failures.
- dispatch accept runs in a transaction that creates or finds the unique `subscription_matches.idempotency_key`.
- manual `/api/discovery/run/*` validates source/subscription/profile state before enqueue.

`jobs.status` remains `pending/running/done/failed`. Partial ingest success is represented on `subscription_matches`, not by inventing new job terminal statuses.

## 8. Admin API / UI

Discovery routes mount inside the authenticated control-plane group but also call an explicit admin check in every handler.

API:

```text
GET/POST/PATCH /api/discovery/subscriptions
GET/POST/PATCH /api/discovery/sources
GET/POST/PATCH /api/discovery/producer-profiles
GET/POST/PATCH /api/discovery/rule-profiles
POST          /api/discovery/rule-profiles/{id}/test
GET           /api/discovery/candidates
GET           /api/discovery/matches
POST          /api/discovery/matches/{id}/accept
POST          /api/discovery/matches/{id}/reject
POST          /api/discovery/matches/{id}/retry
POST          /api/discovery/run/source/{id}
POST          /api/discovery/run/subscription/{id}
GET           /api/discovery/debug/resources/{id}/raw
```

Raw debug endpoint:

- disabled by default in config
- admin-only
- returns redacted and capped output
- records an audit row in `discovery_raw_access_events`
- never appears in list/search UI

UI panels:

- Subscriptions
- Sources / Telegram channels
- Producer profiles
- Rule profiles + test scoring
- Candidates
- Matches / dispatch history
- Discovery runs

All UI rendering treats Telegram text, TMDB metadata, poster URLs, and image references as hostile. Templates must escape text, reject raw HTML/Markdown insertion, reject SVG/HTML images, and use safe image serving headers for cached poster assets.

## 9. Error handling

Error classes:

| Class | Examples | Action |
|---|---|---|
| `auth_failed` | invalid TG session, revoked TMDB key | disable source/profile until admin fixes |
| `rate_limited` | Telegram FloodWait, TMDB 429 | set backoff, do not mark subscription failed |
| `temporary_unavailable` | network timeout, TMDB/poster 5xx | retry with backoff |
| `parse_error` | malformed message/poster item | candidate rejected or review |
| `unsupported_provider` | non-115 resource in v0.3 gate | store candidate, no dispatch |
| `producer_validation_failed` | unsafe profile or missing refs | fail match before enqueue |
| `producer_failed` | producer exit non-zero / timeout | fail match, retain retry action |
| `ingest_partial_failure` | job done but item failed | fail or review match based on result evidence |

Cursor advancement rule:

- Telegram channel cursor advances only after candidate/match writes for processed messages are durable.
- Crash before durable write may re-read messages; idempotency handles duplicates.
- Crash after durable write may resume from cursor.

## 10. Security

### Secrets

`internal/secrets` provides:

- `ValidateRef(root, ref)`
- `Resolve(root, ref)`
- `ResolveEnv(ref)`
- `RedactRef(ref)`

It preserves current roots:

- global `secrets_root` for Emby, TMDB, Telegram source refs
- `producer.secrets_root` for producer cookie/recycle refs

New API writes validate `env:` / `ref:` shape synchronously. Workers resolve refs only at use time.

### Redaction

Redaction must cover:

- `receive_code`
- `share_url` password query parameters
- `api_hash`
- `api_key`
- `tmdb_key`
- `session_ref`
- Telegram session paths
- camelCase and snake_case key variants
- discovery job payloads and error strings

### Poster SSRF controls

Poster HTTP client:

- allows only `http` / `https`
- uses domain allowlist
- disables proxy environment use
- custom `DialContext` rejects private, loopback, link-local, multicast, unspecified, IPv4-mapped IPv6, and Unix targets
- re-resolves and revalidates every redirect
- caps redirect count
- enforces request timeout
- enforces body size limit after decompression
- MIME-sniffs response and rejects HTML/SVG as images
- enforces pixel-count limits for decoded images

### Readiness

TG/TMDB/poster do not hard-fail `/readyz` by default. Readiness reports last-known discovery dependency health and only hard-fails if an explicit operator config says so.

## 11. Testing

### Unit tests

- `internal/secrets`: env/ref validation, symlink escape, non-regular files, redaction.
- `internal/discovery/rules`: feature parsing, disabled rules, deterministic score tuples.
- `internal/discovery/tmdb`: cache key, TTL, stale read, outage classification.
- `internal/discovery/dispatch`: profile-to-payload mapping, provider=115 enforcement, unsafe args rejection, shared producer validation.
- schema/config/sqlc: migrations up/down, FK/unique constraints, generated query round-trips, discovery config validation.

### Fake integration tests

- Fake Telegram: cursor persistence, duplicate message idempotency, FloodWait backoff, auth failure persistence, single channel failure isolation, restart resume.
- Fake poster server: allowlist, redirect SSRF, DNS rebinding/connect-time IP checks, IPv6/local encodings, body expansion, content sniffing.
- Fake TMDB: search/details/cache/stale outage.
- Fake full path: fake Telegram/poster/TMDB -> rules -> candidate/match -> admin accept -> exactly one `ingest_producer` job.
- Concurrent accept: two accept requests on the same match create one dispatch record and one producer job.

### HTTP/UI tests

- `/api/discovery/*`: missing token 401, non-admin user 403, admin 2xx.
- `/ui/discovery/*`: missing token 401, non-admin user 403, admin 2xx.
- public `/` remains data-free.
- UI escaping for hostile TG raw text, TMDB titles, poster URLs.
- raw debug default disabled; when enabled still redacted and capped.

### Manual real release gate

Environment-gated, documented like existing real 115 / real Emby gates.

Requirements:

- existing Telegram session file ref
- private controlled test channel
- pinned message containing a known 115 share
- pinned `115share2cas` tool version
- configured producer profile with valid cookie/recycle refs
- configured sidecar/account/library
- max history window to keep the test bounded

Gate:

1. Crawl controlled channel.
2. Produce one 115 candidate.
3. Match subscription and score.
4. Accept once and concurrently retry accept to prove idempotency.
5. Enqueue one `ingest_producer` job.
6. Producer completes and v0.1 ingest writes `.echo`.
7. `subscription_matches` records success and result references.
8. Existing v0.2 real Emby gate still passes.

## 12. Release gate non-goals

- No real poster full crawl requirement.
- No full TMDB seed.
- No 139 / 189pc automatic producer.
- No Telegram login/session creation.
- No rich poster wall UI.

## 13. Final design decisions

- v0.3 is an internal Echo application layer, not a sidecar.
- Discovery is provider-neutral, but automatic dispatch is 115-only in v0.3.
- Discovery stores candidates and decisions; ingest remains the only writer for resource-pool tables.
- `subscription_matches` is the durable ledger; `current_best_score` is only a cache.
- `internal/secrets` becomes the shared ref boundary for new discovery credentials.
- Discovery API/UI is admin-only.
- Raw discovery data is sensitive and not shown by default.
- The release gate must include fake full-path integration before real external tests.
