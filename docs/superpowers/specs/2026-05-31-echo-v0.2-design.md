# Echo v0.2 设计

- 日期: 2026-05-31
- 作者: Echo 项目
- 状态: 设计稿,待评审
- 范围: 只设计 v0.2;不写实现代码

## 1. 项目定位

Echo v0.2 是建在 v0.1 资源池之上的 Rose-like / NextEmby-like 媒体代理层。v0.2 不重新实现 CAS ingest、不重写云盘 driver、不 import sidecar Go 包,而是消费 v0.1 已落地的 `library_entries` / `file_copies` / manifest / restore / stream 能力,让 Emby 里的 `.echo` 占位资源可被透明播放。

一句话: **Echo 作为 Emby 前置反向代理,拦截并结构化改写 `/Items/{id}/PlaybackInfo`,把已映射到 Echo 资源池的媒体播放 URL 接管到 `/emby/stream/{token}`,再由 Echo 复用 v0.1 stream plane 做用户感知、多账号池、多副本 fallback 与配额计量。**

### v0.2 目标

包含:
- Emby 前置反向代理: 客户端把 Emby server 地址配置为 Echo `/emby` proxy base。
- PlaybackInfo JSON AST 改写: 只结构化改写 Emby 播放信息里的 allowlist 字段,不做全局字符串替换。
- Emby item -> Echo `library_entries.id` 映射: 通过配置的 Emby 路径前缀推导 `library_id + rel_path`,查 v0.1 `library_entries` 得到 `library_entry_id`。
- 多用户: 用 DB 用户模型替换 v0.1 单静态 admin token,同时保留 `users.id='admin'` 兼容 v0.1 历史 `owner_id='admin'`。
- Emby user -> Echo user 映射: upstream Emby 认证通过后,由 `emby_user_links` 绑定到 Echo user。
- Cookie 池 / 账号池: Echo 不保存云盘原始 cookie,只管理用户可用的 v0.1 `accounts` 引用池。
- per-user 配额: 以实际 stream 写出字节数和正在传输的 stream 请求数计量。
- 坏副本剔除与 fallback: 修正 v0.1 Phase 7 sidecar 错误模型,不再依赖真机不存在的 404/410 dead 信号。

不包含:
- Emby 插件。
- 独立 PlaybackInfo 改写服务作为主路径。
- Emby 转码管线接管、HLS master/segment URL 接管、外挂字幕 URL 全量接管。
- Jellyfin 正式兼容;v0.2 只承诺 Emby,Jellyfin best-effort。
- TG/TMDB/订阅/海报墙,留给 v0.3。
- 真实文件上传 fallback。
- Echo 内保存、刷新或登录 115/139/189 原始 cookie。

### v0.1 边界继承

v0.2 必须继承 v0.1 已拍板边界:

- Echo 与 OpenList sidecar 仍以 HTTP REST 进程边界交互。
- 不 import `openlist-guangyapan-src` Go 包。
- 不重写 `store/ingest/sidecarclient/castree` 的核心职责。
- 不把 cas-pipeline stage 编排放进 Echo。
- 不做真实上传 fallback。
- 不接受任意本地绝对路径 restore;所有播放必须落到 `library_entries`。
- v0.1 R1/R2 已拍板工程决策不回头。

## 2. 架构与模块

### 部署形态

```
Emby client
    |
    | Emby server URL = https://echo.example.com/emby
    v
+--------------------------------------------------+
| Echo v0.2                                        |
|                                                  |
|  /emby/* reverse proxy                           |
|    - ordinary Emby requests: transparent proxy    |
|    - /Items/{id}/PlaybackInfo: JSON AST rewrite   |
|    - /emby/stream/{token}: controlled playback    |
|                                                  |
|  v0.2 app layer                                  |
|    - users / emby_user_links                      |
|    - emby_library_mappings / item_mappings        |
|    - playback_sessions / playback_error_tokens    |
|    - playback_events                              |
|    - account_pool_assignments / quota policies    |
|                                                  |
|  v0.1 resource pool                              |
|    - library_entries / blobs / file_copies        |
|    - restore.Resolver / stream proxy              |
|    - sidecarclient HTTP REST                      |
+----------------------+---------------------------+
                       |
                       | HTTP REST
                       v
              OpenList sidecar
                       |
                       v
                 cloud providers

Echo also proxies ordinary Emby API requests to upstream Emby:

+-------------------+       HTTP       +------------------+
| Echo /emby/*      | <--------------> | upstream Emby    |
+-------------------+                  +------------------+
```

### Route namespace

v0.2 固定以下路由边界:

| 路由 | 说明 |
|---|---|
| `/api/*` | Echo 管理/API;不进入 Emby proxy |
| `/ui/*` | Echo 管理 UI;不进入 Emby proxy |
| `/healthz` `/readyz` `/metrics` | 运维 endpoint |
| `/emby/*` | Emby upstream proxy namespace |
| `/emby/Items/{item_id}/PlaybackInfo` | PlaybackInfo 改写入口,支持 GET/POST |
| `/emby/stream/{token}` | Echo 受控播放入口,支持 GET/HEAD |
| `/emby/error/{token}` | Echo 受控错误入口,用于没有可签发 playback session 的 mapped source |

Echo 保留路由优先级必须高于 proxy fallback。`/emby/stream/*`、未来的受控 error URL、`/api/*`、`/ui/*`、运维 endpoint 绝不能落入 upstream proxy。Error token / 受控错误 URL 必须命中 Echo 保留路由,不得进入 `/emby/*` upstream fallback。其余 `/emby/*` 才去掉 `/emby` 前缀后转发到 `emby_servers.base_url`。实现可以把 `proxy_prefix` 配置化,但 v0.2 spec 与测试以 `/emby` 为默认。

PlaybackInfo 不直接写出 v0.1 `/api/restore/{file_id}` 或 `/api/stream/{file_id}`。这些路由继续属于 Echo 管理/API 边界和 v0.1 兼容面;Emby 客户端只看到 `/emby/stream/{token}` 或 `/emby/error/{token}`。`/emby/stream` 是用户感知、配额感知、account-pool 感知的播放包装层,内部才复用 v0.1 resolver/sidecar 能力。

### Proxy 行为

普通 Emby 请求:

- 透传 method、query、body 和 allowlist headers。
- 剔除 hop-by-hop headers。
- 不强制 `Accept-Encoding: identity`。
- `Location` 指向 upstream Emby base URL 时重写到 Echo public base + proxy prefix;外部第三方 Location 保留。
- `Set-Cookie` 默认透传,但去掉 upstream `Domain`,把 `Path` 限制到 configured `proxy_prefix` (默认 `/emby`),并保留/规范化 `Secure`、`SameSite`。
- 不改响应 body。

普通 proxy 不是播放绕过通道。任何 `/emby/*` 下疑似播放、下载、转码、stream 的 endpoint (例如 `/Videos/.../stream`、旧缓存播放 URL、download/transcode API) 必须先做 playback guard:如果能通过 item/path/session evidence 映射到 Echo library,则必须接管到 Echo stream 或返回受控错误;不能作为 ordinary proxy 透传 upstream 播放 URL。无法映射且无历史 mapped evidence 的普通 Emby 资源才透明透传。

Phase 3 中 mapping/guard 尚未完整落地时,所有疑似播放 endpoint 默认 deny,只允许普通非播放 API 透明 proxy;到 Phase 4 path mapping + PlaybackInfo rewrite + proxy guard golden tests 通过后,才允许根据 mapping 细分接管或透传。

PlaybackInfo 请求:

- 请求 upstream 时强制 `Accept-Encoding: identity`。
- upstream 非 2xx 或 `Content-Type` 非 JSON 时,若无法判断 mapped 且响应不含可播放 redirect/Location,原样透传;若该 `item_id` 曾有有效 `emby_item_mappings`、mapping cache 命中、疑似播放 session evidence、或能通过已配置 mapping 判断为 mapped,必须 fail closed。
- JSON AST 解析和字段 allowlist 改写。
- 改写后重新计算 `Content-Length`,移除 `Content-Encoding`。
- 补 `Cache-Control: no-store`,避免客户端长期缓存含过期 token 的 PlaybackInfo。

### 新增包建议

遵循 v0.1 包结构,新增模块保持应用层边界:

```
internal/embyproxy/
  proxy.go                  /emby/* reverse proxy
  playbackinfo.go           PlaybackInfo AST parser/rewrite
  mapping.go                Emby path -> library_entry_id
  session.go                playback token/session
  stream.go                 /emby/stream/{token}
  error.go                  /emby/error/{token}
  headers.go                proxy header/cookie/location helpers
  errors.go                 safe client-facing errors

internal/playback/
  resolver.go               user-aware copy resolver
  quota.go                  quota checks and event accounting
  events.go                 playback_events writer

internal/auth/
  users.go                  users/api_tokens/session helpers
```

这些模块可以调用 v0.1 store queries、restore resolver、sidecarclient,但不能把 v0.2 proxy 逻辑塞回 ingest/castree/producer。

## 3. 数据模型

v0.2 在 v0.1 SQLite schema 上做增量迁移。SQLite 仍为唯一承诺数据库;PG 仅作为后续可能性,不在 v0.2 设计中承诺。

### 用户与认证

#### `users`

下面是 Phase 2+ 最终形态。Phase 1 初始 `users` 表先不包含 `quota_policy_id`,避免 FK 指向尚未创建的 `quota_policies`。

```sql
CREATE TABLE users (
  id             TEXT PRIMARY KEY,
  username       TEXT NOT NULL UNIQUE,
  role           TEXT NOT NULL CHECK (role IN ('admin','user')),
  status         TEXT NOT NULL CHECK (status IN ('active','disabled')),
  password_hash  TEXT,
  quota_policy_id INTEGER NOT NULL REFERENCES quota_policies(id),
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL,
  last_login_at  INTEGER
);
```

迁移规则:

- migration 创建保留用户 `id='admin', username='admin', role='admin'`。
- v0.1 现有 `accounts/libraries/blobs/jobs.owner_id='admin'` 保持不变,解释为该保留用户。
- v0.2 后新增用户使用 ULID/UUID。
- 后续若要把 `admin` 也 UUID 化,单独设计迁移;不混入 v0.2。
- Phase 2 创建 `quota_policies` sentinel `period='none'` 后,通过 SQLite table rebuild 给 `users` 增加 `quota_policy_id INTEGER NOT NULL REFERENCES quota_policies(id)`,并把所有既有用户回填到 sentinel policy。
- Phase 2 之后创建用户必须显式绑定 quota policy;未指定时绑定 sentinel policy。

`password_hash` 使用 Argon2id 或 bcrypt;禁止明文、MD5、SHA1 等弱 hash。可允许空值表示该用户只通过 API token 或外部 bootstrap 管理。

#### `api_tokens`

```sql
CREATE TABLE api_tokens (
  id           TEXT PRIMARY KEY,
  user_id      TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name         TEXT NOT NULL,
  token_hash   TEXT NOT NULL,
  scopes       TEXT NOT NULL, -- JSON array: ["admin","read","playback"]
  expires_at   INTEGER,
  last_used_at INTEGER,
  created_at   INTEGER NOT NULL,
  revoked_at   INTEGER
);
```

只存 token hash,不存明文。Scopes 初版仅 `admin/read/playback`;不做复杂 RBAC。Bootstrap admin token 只用于首次创建/恢复 admin token,不作为长期管理凭据。

### Emby 配置与身份映射

#### `emby_servers`

```sql
CREATE TABLE emby_servers (
  id              TEXT PRIMARY KEY,
  name            TEXT NOT NULL,
  base_url        TEXT NOT NULL,
  api_key_ref     TEXT,
  public_base_url TEXT NOT NULL,
  proxy_prefix    TEXT NOT NULL DEFAULT '/emby',
  enabled         INTEGER NOT NULL DEFAULT 1,
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL
);
```

v0.2 默认只启用一个 upstream Emby。多 Emby server 只预留 schema,不做调度。

Source of truth:

- DB 是运行期 source of truth。
- `config.yaml` 中的 upstream/public base/proxy prefix 只作为 bootstrap seed。
- 启动时若 `emby_servers.id` 不存在,按 config 插入;若已存在,默认不覆盖 DB。
- 管理 UI/API 修改只写 DB。需要纯配置部署时,管理员显式设置 `emby_proxy.config_sync=overwrite_on_startup`,并接受重启覆盖 UI 修改的行为。
- `public_base_url` 和 `proxy_prefix` 在 DB 与 config 中必须同时存在;config 顶层值 seed 到默认 upstream row。

`api_key_ref` 支持:

- `env:NAME`
- `ref:relative/path` under configured `secrets_root`

`ref:` 必须使用 `pathsafe.ResolveExistingUnderRoot(secrets_root, refPath)`,禁止任意绝对路径。

#### `emby_user_links`

```sql
CREATE TABLE emby_user_links (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  emby_server_id TEXT NOT NULL REFERENCES emby_servers(id) ON DELETE CASCADE,
  emby_user_id   TEXT NOT NULL,
  emby_username  TEXT,
  echo_user_id   TEXT NOT NULL REFERENCES users(id),
  enabled        INTEGER NOT NULL DEFAULT 1,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL,
  UNIQUE (emby_server_id, emby_user_id)
);
```

允许多个 Emby user 绑定同一个 Echo user。一个 Emby user 同一时间只能绑定一个 Echo user;迁移绑定不改历史 `playback_sessions/events`,历史按当时 `echo_user_id` 保留。

Echo 不自行实现 Emby token 协议。身份状态机:

1. 先把请求交给 upstream Emby 验证。
2. upstream PlaybackInfo 成功后,Echo 从请求上下文提取 `UserId/DeviceId/token`。
3. 必要时使用 upstream Emby API 或 `/Sessions` 补全 user/device。
4. 查 `emby_user_links` 得到 Echo user。
5. 无绑定时,对 mapped media 默认拒绝/受控错误;对 unmapped media 可原样透传。

#### `library_grants`

```sql
CREATE TABLE library_grants (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  library_id   INTEGER NOT NULL REFERENCES libraries(id) ON DELETE CASCADE,
  echo_user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  permission   TEXT NOT NULL CHECK (permission IN ('playback')),
  enabled      INTEGER NOT NULL DEFAULT 1,
  created_by   TEXT REFERENCES users(id),
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  UNIQUE (library_id, echo_user_id, permission)
);
```

`libraries.owner_id` 仍是隐式 owner 授权。`library_grants` 是 v0.2 最小共享表,只表达“某 Echo user 可播放某 library”,不做目录级 ACL、读写权限或复杂继承。多个 Emby user 绑定到不同 Echo user 时,可以通过 grant 共享同一个 v0.1 admin-owned library,同时 quota 仍按各自 `echo_user_id` 计量。

### Library mapping 与 item cache

#### `emby_library_mappings`

```sql
CREATE TABLE emby_library_mappings (
  id                    INTEGER PRIMARY KEY AUTOINCREMENT,
  emby_server_id        TEXT NOT NULL REFERENCES emby_servers(id) ON DELETE CASCADE,
  library_id            INTEGER NOT NULL REFERENCES libraries(id) ON DELETE CASCADE,
  emby_path_prefix      TEXT NOT NULL,
  emby_path_prefix_norm TEXT NOT NULL,
  echo_rel_prefix       TEXT NOT NULL DEFAULT '',
  case_sensitive        INTEGER NOT NULL DEFAULT 1,
  enabled               INTEGER NOT NULL DEFAULT 1,
  created_at            INTEGER NOT NULL,
  updated_at            INTEGER NOT NULL
);
```

映射规则:

- 只允许 configured mapping -> `library_id + rel_path` -> v0.1 `library_entries`。
- 禁止任意本地绝对路径反查。
- 多 mapping 命中时最长前缀优先。
- prefix 匹配大小写由 `case_sensitive` 控制。
- 对输入路径统一 `/` 与 `\`,只做一次 percent decode。
- 拒绝 NUL、控制字符、`..`、Windows drive 越界、UNC 越界、Unicode slash 绕过。
- mapping 的 `library_id` 必须属于当前 Echo user 或有 enabled `library_grants(permission='playback')`。管理员创建 mapping 时可以引用任意现有 library,但 PlaybackInfo 改写和 stream 时必须按请求用户重新授权。

#### `emby_item_mappings`

```sql
CREATE TABLE emby_item_mappings (
  id                         INTEGER PRIMARY KEY AUTOINCREMENT,
  emby_server_id             TEXT NOT NULL REFERENCES emby_servers(id) ON DELETE CASCADE,
  emby_item_id               TEXT NOT NULL,
  media_source_id            TEXT NOT NULL,
  mapping_id                 INTEGER NOT NULL REFERENCES emby_library_mappings(id),
  media_source_path_raw      TEXT NOT NULL,
  media_source_path_norm     TEXT NOT NULL,
  path_norm_version          INTEGER NOT NULL,
  library_id                 INTEGER NOT NULL REFERENCES libraries(id),
  rel_path                   TEXT NOT NULL,
  library_entry_id           INTEGER NOT NULL REFERENCES library_entries(id) ON DELETE CASCADE,
  blob_id                    INTEGER NOT NULL REFERENCES blobs(id),
  library_entry_updated_at   INTEGER NOT NULL,
  emby_item_etag             TEXT,
  last_seen_at               INTEGER NOT NULL,
  created_at                 INTEGER NOT NULL,
  updated_at                 INTEGER NOT NULL,
  UNIQUE (emby_server_id, emby_item_id, media_source_id, media_source_path_norm)
);
```

`emby_item_mappings` 只缓存成功 mapped 的 source,不缓存 unmapped 或失败状态。缓存命中后必须校验:

- `library_entry_id` 仍存在。
- `blob_id` 与 `library_entry_updated_at` 未变。
- `mapping_id` 仍 enabled。
- `path_norm_version` 与当前实现一致。
- `library_entries.library_id = emby_item_mappings.library_id`。
- `library_entries.blob_id = emby_item_mappings.blob_id`。

不一致则重新解析路径并更新缓存。

`emby_item_mappings` 是路径解析缓存,不是授权缓存。每次 PlaybackInfo 改写和每次 `/emby/stream/{token}` 都必须按当前 `echo_user_id` 重新校验 owner/grant,不能因为缓存命中而跳过授权。

### Playback session 与 events

#### `playback_sessions`

`playback_sessions` 在 Phase 3 与 `emby_servers` 一起创建;Phase 2 只创建 quota/event 骨架,不签发 stream token。

```sql
CREATE TABLE playback_sessions (
  id                   TEXT PRIMARY KEY,
  selector             TEXT NOT NULL UNIQUE,
  token_hash           TEXT NOT NULL,
  echo_user_id          TEXT NOT NULL REFERENCES users(id),
  emby_server_id        TEXT NOT NULL REFERENCES emby_servers(id),
  emby_user_id          TEXT NOT NULL,
  device_id             TEXT,
  item_id               TEXT NOT NULL,
  media_source_id       TEXT NOT NULL,
  emby_play_session_id  TEXT,
  library_entry_id      INTEGER REFERENCES library_entries(id),
  blob_id               INTEGER REFERENCES blobs(id),
  prefer_provider       TEXT,
  state                 TEXT NOT NULL CHECK (state IN ('active','expired','revoked','failed')),
  failure_reason        TEXT,
  created_at            INTEGER NOT NULL,
  last_seen_at          INTEGER NOT NULL,
  expires_at            INTEGER NOT NULL,
  CHECK (
    (state = 'active' AND library_entry_id IS NOT NULL AND blob_id IS NOT NULL)
    OR state IN ('expired','revoked','failed')
  )
);
```

Token 形态: `selector.secret`。

- DB 存 selector 和 secret hash。
- access log / metrics / events 只记录 session id 或 token hash prefix,不记录 selector/secret 原文或完整 token。
- token 绑定 Echo user、Emby user、device、item、media source、session。
- token 可在 TTL 内支持多次 Range、seek、重试和续播。
- token 可撤销。
- 响应加 `Referrer-Policy: no-referrer`。
- `/emby/stream/{token}` 不走 admin bearer,也不依赖 upstream Emby cookie。

Session 只代表已通过用户绑定、授权、配额与基础 resolver 检查的候选播放。普通拒绝不创建 session,而是签发 `playback_error_tokens`。Session 不固定 `file_copies.id`;实际 stream 时动态 resolver 选择 copy。最终使用 copy 写入 `playback_events`。

#### `playback_error_tokens`

```sql
CREATE TABLE playback_error_tokens (
  id                   TEXT PRIMARY KEY,
  selector             TEXT NOT NULL UNIQUE,
  token_hash           TEXT NOT NULL,
  echo_user_id          TEXT REFERENCES users(id),
  emby_server_id        TEXT REFERENCES emby_servers(id),
  emby_user_id          TEXT,
  device_id             TEXT,
  item_id               TEXT,
  media_source_id       TEXT,
  reason               TEXT NOT NULL CHECK (reason IN (
    'unauthorized',
    'quota_exceeded',
    'account_unavailable',
    'temporary_unavailable',
    'no_live_copy',
    'rewrite_failed',
    'unsupported_transcode',
    'unknown_playable_url'
  )),
  http_status           INTEGER NOT NULL,
  created_at            INTEGER NOT NULL,
  expires_at            INTEGER NOT NULL
);
```

Error token 形态同样是 `selector.secret`,但只用于 `/emby/error/{token}`。它不引用 `playback_sessions`,不要求 `echo_user_id` 非空,用于以下场景:

- upstream Emby 已认证但没有 `emby_user_links` 绑定。
- mapped source 因 quota/account pool/no live copy/rewrite failure 不能签发 active session。
- mapped source 只有 unsupported `TranscodingUrl` 或 unknown playable URL-like 字段。

`/emby/error/{token}` 只返回受控错误 HTTP 状态与安全枚举原因,不进入 resolver,不触发 sidecar,不扣 bytes quota。它可以记录 `playback_events.operation='playback_info'` 的失败事件;无 `echo_user_id` 时只记录 request/item/media source 安全维度。

#### `playback_events`

```sql
CREATE TABLE playback_events (
  id                INTEGER PRIMARY KEY AUTOINCREMENT,
  request_id        TEXT NOT NULL,
  session_id        TEXT,
  error_token_id    TEXT,
  echo_user_id       TEXT REFERENCES users(id),
  library_entry_id   INTEGER,
  blob_id            INTEGER,
  copy_id            INTEGER,
  provider           TEXT,
  account_id         TEXT,
  operation          TEXT NOT NULL CHECK (operation IN ('playback_info','stream','stream_probe')),
  status             TEXT NOT NULL,
  bytes_sent         INTEGER NOT NULL DEFAULT 0,
  range_header       TEXT,
  http_status        INTEGER,
  failure_kind       TEXT,
  failure_message    TEXT,
  started_at         INTEGER NOT NULL,
  finished_at        INTEGER
);
```

`playback_events` 是审计/计量事实表,不是 session lifecycle 表。`session_id` 与 `error_token_id` 保存 nullable snapshot TEXT,不建 FK:这样 Phase 2 可在 `playback_sessions/playback_error_tokens` 创建前独立落库,后续 session/token 清理也不会破坏历史事件。

计量规则:

- 每个 HTTP stream response 是一条事件。
- `/emby/stream` 事件必须有 `session_id` 和 `echo_user_id`;Phase 2 的 resolver/quota 单元测试事件可不带 session。
- `/emby/error` 或 PlaybackInfo 签发失败可带 `error_token_id`,不计 bytes quota。
- 按实际写给客户端的 bytes 增量累计。
- session 只是关联维度,不是去重键。
- 客户端中断记录已写 bytes。
- Range、seek、重试分别记录事件。
- `range_header` 限长保存。

### 配额与账号池

#### `quota_policies`

```sql
CREATE TABLE quota_policies (
  id                    INTEGER PRIMARY KEY AUTOINCREMENT,
  name                  TEXT NOT NULL,
  period                TEXT NOT NULL CHECK (period IN ('day','month','rolling_24h','none')),
  max_bytes             INTEGER,
  max_streams           INTEGER,
  max_playback_sessions INTEGER,
  version               INTEGER NOT NULL DEFAULT 1,
  created_at            INTEGER NOT NULL,
  updated_at            INTEGER NOT NULL
);
```

`period='none'` 表示不限制 bytes/streams/sessions;此时其它 max 字段忽略。

#### `quota_usage`

```sql
CREATE TABLE quota_usage (
  user_id          TEXT NOT NULL REFERENCES users(id),
  quota_policy_id  INTEGER NOT NULL,
  policy_version   INTEGER NOT NULL,
  period_start     INTEGER NOT NULL,
  period_end       INTEGER NOT NULL,
  bytes_used       INTEGER NOT NULL DEFAULT 0,
  stream_count     INTEGER NOT NULL DEFAULT 0,
  updated_at       INTEGER NOT NULL,
  PRIMARY KEY (user_id, quota_policy_id, policy_version, period_start, period_end)
);
```

`quota_usage` 只是历史用量缓存,权威事实是 `playback_events`。`quota_policy_id` 必须非空;无限额用户默认绑定 sentinel `period='none'` policy,用户创建/迁移时必须补齐该绑定,避免 SQLite composite primary key 中出现多个 NULL policy rows。`stream_count` 表示该 period 内已完成/已记录的 stream response 次数,不是当前并发;`stream_probe` 不计入 `stream_count`。当前 active stream 从内存租约 + unfinished `playback_events(started_at IS NOT NULL AND finished_at IS NULL)` 计算;进程崩溃后,启动 reconcile 将超过 stream timeout 的 unfinished event 标为 interrupted,不继续占用并发。Policy 变更时缓存失效,可重算。

#### `account_pool_assignments`

```sql
CREATE TABLE account_pool_assignments (
  id                     INTEGER PRIMARY KEY AUTOINCREMENT,
  echo_user_id            TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  account_id              TEXT NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  provider                TEXT NOT NULL,
  priority                INTEGER NOT NULL DEFAULT 100,
  weight                  INTEGER NOT NULL DEFAULT 1,
  max_concurrent_streams  INTEGER,
  daily_bytes_limit       INTEGER,
  enabled                 INTEGER NOT NULL DEFAULT 1,
  created_at              INTEGER NOT NULL,
  updated_at              INTEGER NOT NULL,
  UNIQUE (echo_user_id, account_id)
);
```

排序规则:

1. preferred provider。
2. account `priority` 升序。
3. 同 priority 内稳定 weighted choice,hash key 为 `echo_user_id + library_entry_id + session selector + copy_id`。
4. `file_copies.last_seen DESC`。

`provider` 是 `accounts.provider` 的查询快照,用于索引和展示;写入和查询时必须校验它与 referenced `accounts.provider` 一致,不一致则拒绝配置或在 migration/reconcile 中修正。

## 4. 数据流

### PlaybackInfo 改写流

```
Client
  -> GET/POST /emby/Items/{item_id}/PlaybackInfo
  -> Echo proxy
      1. force Accept-Encoding: identity for upstream PlaybackInfo
      2. upstream Emby authenticates request and returns JSON
      3. Echo extracts Emby user/device/token context
      4. Echo maps Emby user -> Echo user
      5. parse JSON AST
      6. for each MediaSources[]:
         a. map Path/URL to library_id + rel_path
         b. resolve library_entries.id
         c. check user authorization/quota/account pool/live copy existence
         d. create playback_session or playback_error_token
         e. rewrite all playable URLs to Echo stream/error URL
         f. clean RequiredHttpHeaders
      7. return rewritten JSON
```

映射优先级:

1. `MediaSources[].Path`
2. allowlisted upstream Emby URL fields if they can be normalized through configured `emby_library_mappings`
3. unmapped

URL/path 反推必须经 configured mapping,不能接受任意 path。

### Field matrix

#### 用于映射/缓存,默认不改

| 字段 | 行为 |
|---|---|
| `MediaSources[].Id` | 作为 `media_source_id` 存 mapping/session;不改 |
| `MediaSources[].Path` | 用于 mapping。mapped source 中若 `Path` 是 URL-like、`.strm` URL、带签名 query、或任何客户端可能直接使用的 playable locator,必须改写为 Echo URL、脱敏为非播放占位值,或让 source 受控错误;只有纯展示/本地非 URL path 才可在 `redact_mapped_path=false` 时保留 |
| `MediaSources[].Name` / `Size` / `RunTimeTicks` / `ETag` | 用于缓存校验/日志;不改 |

v0.2 默认 `redact_mapped_path=true`,mapped source 的 `Path` 默认脱敏为非播放占位值。只有兼容性测试证明客户端需要纯展示本地路径时,才允许管理员显式设为 false;该开关不允许保留 URL-like/playable locator。

#### 保留不改

| 字段 | 行为 |
|---|---|
| `PlaySessionId` | 保留 |
| `MediaSources[].MediaStreams` | 音轨、字幕轨、视频流信息保留 |
| `Container` / `Bitrate` / `Formats` | 保留 |
| `DefaultAudioStreamIndex` / `DefaultSubtitleStreamIndex` | 保留 |
| `SupportsTranscoding` / `SupportsDirectStream` / `SupportsDirectPlay` | 保留 |
| `TranscodingContainer` / `TranscodingSubProtocol` / 转码参数 | 保留,但 mapped source 的可播放 URL 不回源 |

#### mapped source 必须接管或受控错误

总规则: **只要 source 已映射到 Echo library,所有可播放 URL 字段都不能保留 upstream Emby URL。**

| 字段 | 行为 |
|---|---|
| `MediaSources[].DirectStreamUrl` | 改为 `/emby/stream/{token}` 或 `/emby/error/{token}` |
| `MediaSources[].StreamUrl` | 改为 `/emby/stream/{token}` 或 `/emby/error/{token}` |
| `MediaSources[].TranscodingUrl` | v0.2 不接管 Emby 转码;若 mapped source 只有转码 URL,改为受控错误 URL,不回 upstream |
| allowlist 外 `*Url` 字段 | mapped source 中发现未知 URL-like 字段时 fail closed:除非该字段在 allowlist 中被证明不是播放用途,否则该 source 改为受控错误或拒绝,不能保留 upstream URL |

#### RequiredHttpHeaders

Mapped source 的 `RequiredHttpHeaders` deny-by-default:

- 默认删除或设为空对象。
- 只保留 Echo stream 明确需要且安全的 allowlist header。
- 禁止透出 `Authorization`、`Cookie`、`X-Emby-Token`、`api_key`、OpenList/sidecar 私有 header。

Unmapped source 作为普通 Emby 内容透明保留 upstream `RequiredHttpHeaders`;mapped source 一律先清空再按 Echo allowlist 重建。

### `/emby/stream/{token}` 流程

```
GET /emby/stream/{selector.secret}
  1. parse selector, hash secret, lookup playback_session
  2. check state, expiry, user/session binding
  3. only active sessions continue; expired/revoked/failed return controlled 403/404/410
  4. quota and active stream check
  5. ResolveCopies(echo_user_id, library_entry_id, prefer_provider)
  6. try candidates before headers are sent
  7. once headers are sent, no fallback
  8. count actual bytes written
  9. record playback_events and copy_failures
```

HEAD 行为:

- 不按 GET 后丢 body 实现。
- 可做轻量 metadata/probe。
- 记录为 `playback_events.operation='stream_probe'` 时,只记录请求事实和结果,不占长期并发,不扣 bytes quota。
- 不按完整文件大小扣 quota。
- 是否调用 sidecar 必须由实现显式测试;默认不触发昂贵全量流。

Range 行为:

- 透传 `Range`、`If-Range`、`If-Modified-Since`、`If-None-Match`、`User-Agent` 到 sidecar stream。
- 返回 `200/206/304/416` 与 `Content-Range`、`Accept-Ranges`、`Content-Length` 等 allowlist headers。
- 206 seek 只计实际发送 bytes。

### User-aware resolver

`ResolveCopies(ctx, echo_user_id, library_entry_id, prefer_provider)`:

1. 校验 `library_entry_id -> library_id -> libraries.owner_id` 属于 `echo_user_id`,或存在 enabled `library_grants(permission='playback')`。
2. 取 blob_id。
3. join `file_copies` + `account_pool_assignments` + `accounts`。
4. 过滤:
   - `file_copies.status='live'`
   - `file_copies.scheduler_state NOT IN ('confirmed_dead','suspect_dead')`
   - account pool enabled
   - account `status` 和本地 `scheduler_state` 可用
   - copy/account 不在 cooldown
   - 未超过账号并发/配额
5. 排序并返回候选。
6. 默认最多尝试 5 个候选,可配置。

## 5. 错误处理与降级

### Phase 7 前置: sidecar 真机错误模型

v0.2 开工前必须先完成:

1. `integration/real_115_test.go` 真机主路径: 小样本 `.cas tree` -> manual import -> PutCAS -> restore JSON -> stream 首段。
2. sidecar 错误模型对齐:
   - OpenList JSON API 错误是 HTTP 200 + body `code/message`。
   - `/d/` 下载失败多是 HTTP 500 + HTML。
   - 真机没有可靠 404/410 dead 信号。
   - v0.1 `MarkDead` 不能继续依赖 404/410。

这些是 v0.1 前置补丁:只扩展错误类型、状态字段和调度元数据,不替换 sidecarclient HTTP 边界,不改 ingest/store 核心模型语义。

### Typed errors

```go
type SidecarErrorKind string

const (
    SidecarErrProtocol         SidecarErrorKind = "protocol"
    SidecarErrTransport        SidecarErrorKind = "transport"
    SidecarErrAPIEnvelope      SidecarErrorKind = "api_envelope"
    SidecarErrObjectMissing    SidecarErrorKind = "object_missing"
    SidecarErrStorageMissing   SidecarErrorKind = "storage_missing"
    SidecarErrStorageUnhealthy SidecarErrorKind = "storage_unhealthy"
    SidecarErrAuthOrAccount    SidecarErrorKind = "auth_or_account"
    SidecarErrTransient        SidecarErrorKind = "transient"
)

type SidecarTypedError struct {
    Kind         SidecarErrorKind
    Operation    string
    HTTPStatus   int
    OpenListCode int
    SafeMessage  string
    RawMessage   string // debug-only; disabled by default and never logged raw
}
```

分类:

- transport/dial/timeout -> `transport`。
- HTTP/JSON shape/schema 错误 -> `protocol`。
- 合法 OpenList envelope 但 `code != 200` -> `api_envelope`,再按 safe message 分类。
- `object not found` / `failed to get file: object not found` -> `object_missing`,前提是不同时命中 storage/auth 信号。
- `storage not found` / `please add a storage first` / rawPath mount 缺失 -> `storage_missing`。
- `access_token is empty` / `refresh token failed` / `http 401` / `unauthorized` / `forbidden` -> `auth_or_account`。
- admin storage/list mount `status != work` -> `storage_unhealthy`。
- 其它 code=500/upstream 错误 -> `transient`。

除非后续真机证据证明需要兼容,`code=0` 不作为成功码。

### confirmed vs suspect dead

`confirmed_dead`:

- 只来自 high-confidence `link` JSON API 分类。
- 已知 operation、已知 remote path。
- message 命中 object-missing 白名单。
- 不同时命中 storage/auth 信号。

`suspect_dead`:

- `/d/` 500 HTML。
- 模糊 message。
- low-confidence 分类。

Suspect 只能写审计/失败计数,必须经后台 verify 或多次 link 探测确认后才 mark dead。

### Stream failure 口径

- sidecar headers 发送前失败: 记录失败,按策略尝试下一个 copy。
- headers 已发后: 不 fallback。
- 客户端取消、seek、Range 重试: 不算 copy 失败。
- 上游 body 读取中断: 记录 `upstream_read_error/interrupted`,不立即 dead。
- 完整 EOF 或达到本次 Range 预期字节: 才降低/清理失败分并更新 `last_seen`。

### Account/storage cooldown

`storage_missing`、`auth_or_account`、`storage_unhealthy` 更新 Echo 本地调度状态:

- `cooldown`
- `unhealthy`
- `token_suspect`

Echo 不持有 sidecar cookie,不承诺修复 sidecar 凭据。恢复方式:

- TTL 自动过期。
- 手动 recheck。
- `storage/list` 成功后恢复。

### Client-facing errors

`X-Echo-Reason` 只允许安全枚举:

- `quota_exceeded`
- `account_unavailable`
- `temporary_unavailable`
- `no_live_copy`
- `unauthorized`

不暴露 storage mount、account id、OpenList message、签名 URL。

最终 HTTP 状态:

- 无权限: 403 或隐藏存在性时 404,且不进入 copy 解析。
- 无 live copy / all confirmed dead: 404。
- `/d/` 500 HTML 或 suspect dead 不能转成永久 404/MarkDead;这类失败走 `temporary_unavailable`/503 或受控错误,直到 link/verify 确认为 confirmed dead。
- 配额命中: 429。
- 临时 sidecar/account 问题: 503。
- mapped source 的 resolver / sidecar / account transient failure 只能返回 503 或受控错误 URL,不得 fallback 到 upstream Emby playable URL。

### Golden tests

保存脱敏 Emby PlaybackInfo fixture:

- 单 source: `Path + DirectStreamUrl`。
- 多 source / 多版本。
- 只有 `TranscodingUrl`。
- 带 `RequiredHttpHeaders`。
- mapped source 的 `Path` 是 URL-like / `.strm` URL / 带签名 query / playable locator。
- mapped source 带 unknown `FooUrl` + `RequiredHttpHeaders.Authorization/Cookie/X-Emby-Token/api_key`。
- gzip upstream PlaybackInfo JSON。
- unmapped。
- mapped quota exceeded。
- mapped no account pool。
- mapped rewrite failure。
- mapping 修改、禁用、重叠前缀后旧 `emby_item_mappings` cache 失效并重建。
- upstream PlaybackInfo 非 JSON/非 2xx 且 item 有 mapped evidence 时 fail closed。

断言:

- unmapped 原样,不生成 token、不写 `playback_sessions`、不触发 resolver/quota。
- mapped source 所有播放 URL 都是 Echo URL 或受控错误 URL。
- mapped URL-like/playable `Path` 被改写、脱敏或受控错误,不能保留 upstream locator。
- unknown URL-like 字段 fail closed,除非 allowlist 证明不是播放用途。
- mapped 只有 `TranscodingUrl` 时不回源。
- `PlaySessionId`、`MediaStreams`、`Supports*`、`Container`、`Bitrate` 保留。
- `RequiredHttpHeaders` 不泄露 token/cookie/auth。
- `Content-Length` 正确,`Content-Encoding` 移除。

### Integration tests

- fake Emby + fake sidecar: PlaybackInfo -> `/emby/stream` -> fake sidecar stream 206。
- fake sidecar error matrix: object missing fallback、storage missing cooldown、auth account cooldown、transient retry。
- headers/body 已开始写出后 upstream read error 不 fallback。
- 客户端 cancel/seek 不计 confirmed dead。
- `integration/real_115_test.go` 真机主路径作为 v0.2 前置和最终回归。

### Manual release gate

真实 Emby 客户端:

- 配置 Echo `/emby` 为 server。
- 已映射媒体可播放、seek、暂停/继续。
- PlaybackInfo 中既有字幕元数据不被 AST rewrite 删除。
- 未映射媒体仍走 upstream。
- 配额不足、账号池禁用、copy dead 时客户端收到可解释失败。

外挂字幕 URL 不承诺全量代理;若属于 mapped playable URL 且无法安全接管,必须受控错误,不能半接管。

### Readiness

Hard readiness:

- DB ping / migration。
- sidecar error-model contract compatibility **只在已取得有效探测结果时 hard**:首次启动若 sidecar 不可达且未配置 `readiness.require_sidecar_contract=true`,状态为 degraded/unknown,不 hard fail;一旦探测可达但版本或 contract 不兼容,hard fail。若 `emby_proxy.playback.mapped_only=true` 或显式 `readiness.require_sidecar_contract=true`,unknown 也 hard fail。

Soft degraded:

- sidecar 当前连通性默认作为 degraded health detail/metric,不让编排器摘掉整个 Echo;若 `readiness.require_sidecar_connectivity=true` 或 `emby_proxy.playback.mapped_only=true`,作为 hard dependency。
- Emby upstream connectivity 默认只作为 degraded health detail/metric,不让编排器摘掉整个 Echo;若 `readiness.require_emby_connectivity=true`,作为 hard dependency。
- 可配置为 hard dependency,但默认关闭。

## 12. 已确认的设计决策

- Emby 集成形态: Echo 前置反代 + PlaybackInfo JSON AST 改写。
- Route namespace: Emby proxy 固定 `/emby/*`,Echo 管理面保持 `/api/*` 等。
- 播放入口: `/emby/stream/{selector.secret}`。
- Emby item 映射: path prefix -> `library_id + rel_path` -> `library_entries.id`,缓存到 `emby_item_mappings`。
- 用户迁移: 保留 `users.id='admin'` 兼容 v0.1。
- Cookie 池: Echo account 引用池,不保存原始 cookie。
- 配额: 按实际 stream bytes 和正在传输的 stream 请求计量。
- mapped source: 所有播放 URL 必须 Echo 接管或受控错误,不能回 upstream。
- RequiredHttpHeaders: deny-by-default。
- sidecar dead: confirmed/suspect 双层,不依赖 404/410。
- Phase 0 sidecar 错误模型和 real_115_test 是 v0.2 proxy 开工前置。

## 13. 已否决的方案

- Emby 插件作为 v0.2 主路径。
- 独立 PlaybackInfo 改写服务作为 v0.2 主路径。
- JSON 字符串替换式 rewrite。
- mapped source 回 upstream fallback。
- 302 redirect 作为默认播放形态。
- 真实文件上传 fallback。
- 任意本地 path restore。
- Echo 保存/刷新云盘原始 cookie。
- v0.2 支持 Emby 转码/HLS/外挂字幕 URL 全量接管。
- `api_key_ref` 接受任意绝对路径。

## 14. v0.2 不解决的问题

- TG/TMDB/订阅/海报墙,留 v0.3。
- 多 upstream Emby 调度,只预留 schema。
- Jellyfin 正式兼容。
- WebDAV/S3 `.echo` 输出。
- 跨用户共享库复杂 ACL;v0.2 只做 owner + `library_grants(permission='playback')`,不做目录级/读写级/继承 ACL。
- 自动修复 sidecar cookie 或云盘账号。
- 跨 hash conflict 自动 merge。
