# Echo v0.5 Browser Auth 设计

- 日期: 2026-06-07
- 作者: Echo 项目
- 状态: 已确认方向,待实现计划
- 范围: 只设计 v0.5 browser auth foundation;不写实现代码

## 1. 项目定位

Echo v0.5 的第一阶段是把 v0.4 的 token MVP 用户入口升级为一等浏览器登录入口。

一句话: **Echo 继续保留 DB-backed Bearer API token 作为 CLI / 自动化 / 兼容入口,同时为浏览器提供 cookie session、CSRF 和用户名密码登录,让 admin dashboard 与 `/app` 不再依赖手动粘贴 token。**

v0.5 不重写 v0.1 资源池、v0.2 Emby proxy、v0.3 discovery 或 v0.4 media request。它只新增浏览器认证层,复用现有 `users`、`password_hash`、API token、scope、`auth.UserContext` 和 authenticated route 分组。

### 目标

包含:

- 用户名密码登录,基于现有 `users.username` 与 `users.password_hash`。
- 初始 admin 密码设置,只能通过 `auth.bootstrap_admin_token` 授权。
- 服务端 session 表,浏览器持有 HttpOnly session cookie。
- Session-auth 与 Bearer-auth 共存: 有 Bearer 时优先按现有 API token 验证;没有 Bearer 时再查 session cookie。
- Cookie-auth 的非安全 HTTP 方法必须通过 CSRF 校验。
- `/` admin shell 与 `/app` user shell 改为 session-aware,不再要求用户在页面里粘贴 token。
- `/api/session/me` 返回当前登录用户、安全 scope 投影和当前 CSRF token。
- Logout revoke 当前 session。
- 测试覆盖 session 生命周期、CSRF、scope 隔离和 Bearer 兼容。

不包含:

- OIDC / SAML / LDAP / OAuth 外部登录。
- 邮箱、短信、magic link、验证码、MFA、密码找回邮件。
- 用户自助注册。
- 管理员完整用户管理 UI 重做。
- 把 API token 废弃或迁移为 session。
- 把 Emby playback token、stream token 或 bootstrap token 改成 session。
- 重新设计媒体请求 UX、海报墙、详情页或通知系统。

## 2. 架构

v0.5 在现有认证边界前增加一个 session-capable authenticator:

```text
+------------------------+
| Browser               |
| - /login              |
| - /, /app             |
| - htmx/fetch          |
+-----------+------------+
            |
            | Cookie: echo_session
            | X-CSRF-Token on mutations
            v
+------------------------+
| HTTP auth middleware   |
| 1. Bearer API token    |
| 2. Web session cookie  |
+-----------+------------+
            |
            v
+------------------------+
| auth.UserContext       |
| - user id              |
| - role                 |
| - scopes               |
+-----------+------------+
            |
            v
+------------------------+
| Existing handlers      |
| /api/* /ui/* /app/*    |
+------------------------+
```

关键原则:

- Handler 层继续只看 `auth.UserContext`;不用知道请求来自 Bearer 还是 session。
- Bearer token 语义保持不变,以免破坏 CLI、脚本和已有测试。
- Session 只是一种浏览器凭据。它可以携带 scopes snapshot,但登录时仍必须读取当前用户状态,禁用用户立即失败。
- CSRF 是 cookie-auth 的约束。Bearer-auth 请求不带浏览器 cookie 语义,不要求 CSRF。

## 3. 数据模型

SQLite 继续是唯一承诺数据库。v0.5 新增一次迁移。

### `web_sessions`

服务端 session ledger。Cookie 里只放 opaque `selector.secret`,数据库只保存 selector 和 secret hash。

```sql
CREATE TABLE web_sessions (
  selector       TEXT PRIMARY KEY,
  user_id        TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  secret_hash    TEXT NOT NULL,
  csrf_hash      TEXT NOT NULL,
  scopes         TEXT NOT NULL,
  user_agent     TEXT,
  ip_hint        TEXT,
  created_at     INTEGER NOT NULL,
  last_seen_at   INTEGER NOT NULL,
  expires_at     INTEGER NOT NULL,
  revoked_at     INTEGER
);

CREATE INDEX idx_web_sessions_user ON web_sessions(user_id, revoked_at, expires_at);
CREATE INDEX idx_web_sessions_expiry ON web_sessions(expires_at, revoked_at);
```

Cookie value:

```text
selector.secret
```

Hashing:

- `secret_hash = sha256:<hex>` over the session secret.
- `csrf_hash = sha256:<hex>` over the CSRF token.
- Selector is random and public; secret and CSRF token are random and never stored in plaintext.

### Existing `users.password_hash`

`users.password_hash` already exists and remains nullable.

Password hash format:

```text
argon2id$v=19$m=65536,t=3,p=1$<salt-b64>$<hash-b64>
```

Rules:

- Active browser login requires non-empty `password_hash`.
- The seeded `admin` user starts with `password_hash = NULL`; it cannot log in until bootstrap password setup succeeds.
- Disabled users cannot log in and cannot authenticate existing sessions.

## 4. API

### Public browser routes

`GET /login`

- Renders a data-free login shell.
- If already session-authenticated, redirects to `/app` for ordinary users or `/` for admins.
- Does not expose bootstrap token, password hash details, or user existence.

`GET /`

- Becomes session-aware admin shell.
- If unauthenticated, redirects to `/login`.
- If authenticated without admin scope, returns 403 or links to `/app` without loading admin fragments.

`GET /app`

- Becomes session-aware user shell.
- If unauthenticated, redirects to `/login`.
- If authenticated without `discovery` scope, shell renders a minimal forbidden state; authenticated fragment routes still enforce scope.

### Session JSON routes

`POST /api/session/login`

Request:

```json
{
  "username": "admin",
  "password": "..."
}
```

Behavior:

- Strict JSON, bounded by the existing API body limit.
- Applies same-origin Origin/Referer check before setting cookie.
- Looks up active user by username.
- Verifies Argon2id password hash in constant-time where applicable.
- Creates a new session with scopes derived from role:
  - admin: `["admin"]`
  - user: `["discovery","read","playback"]`
- Sets `Set-Cookie: echo_session=<selector.secret>; HttpOnly; SameSite=Lax; Path=/; Max-Age=<ttl>`.
- Adds `Secure` when the request is HTTPS or config forces secure cookies.
- Returns user projection plus CSRF token.
- All failures return a generic 401.

`POST /api/session/logout`

- Requires valid session cookie and valid CSRF token when authenticated by cookie.
- Revokes the current session.
- Clears the session cookie.
- Bearer-auth logout is a no-op for API tokens and returns 204.

`GET /api/session/me`

Returns:

```json
{
  "authenticated": true,
  "user": {
    "id": "admin",
    "username": "admin",
    "role": "admin",
    "scopes": ["admin"]
  },
  "csrf_token": "..."
}
```

Unauthenticated response:

```json
{
  "authenticated": false
}
```

`POST /api/bootstrap/admin-password`

Request:

```json
{
  "password": "..."
}
```

Behavior:

- Authorized only by `Authorization: Bearer <auth.bootstrap_admin_token>`.
- Sets or rotates the seeded admin user's password.
- Revokes all existing admin web sessions after password rotation.
- Does not create or return an API token.
- Enforces minimum password length 12 bytes and rejects leading/trailing whitespace changes by requiring `password == strings.TrimSpace(password)`.

## 5. Middleware

Current `authmw.AuthFunc` stays the outer shape, but its check function becomes composite:

1. If `Authorization: Bearer ...` exists, authenticate through existing API token logic.
2. Else parse `echo_session` cookie.
3. Load `web_sessions` by selector.
4. Reject revoked or expired sessions.
5. Compare supplied secret hash.
6. Load user by `user_id`; reject disabled or missing users.
7. Decode session scopes and return `auth.UserContext`.
8. Touch `last_seen_at` with bounded write frequency to avoid one DB write per static-like request.

CSRF middleware runs inside authenticated control-plane routes:

- If request method is GET, HEAD, OPTIONS, or TRACE: skip.
- If request authenticated by Bearer: skip.
- If request authenticated by session: require `X-CSRF-Token`.
- Compare header token hash with session `csrf_hash`.
- On failure return 403 JSON for API routes and plain 403 for htmx fragments.

To let CSRF know the credential source, `auth.UserContext` gains a small field:

```go
CredentialSource string // "bearer" or "session"
```

Existing code that ignores the field remains valid.

## 6. Web Shell Changes

`internal/web/static/app.js` changes from localStorage token injector to session helper:

- On DOMContentLoaded, call `/api/session/me`.
- Store CSRF token in memory, not localStorage.
- Attach `X-CSRF-Token` to same-origin htmx/fetch mutations.
- Stop reading `echo_admin_token` and `echo_app_token` from localStorage.
- Keep JSON form serialization for management and media request forms.
- On 401 from htmx/fetch, redirect to `/login`.

`templates.Index`:

- Removes the admin-token password box.
- Keeps admin panels unchanged; fragment routes still enforce admin scope.

`templates.AppShell`:

- Removes app-token input.
- Keeps existing media request panels.

New `templates.Login`:

- Simple username/password form.
- Posts JSON to `/api/session/login`.
- Redirects to requested `next` path if same-origin relative path, else `/app` or `/`.

The login page is intentionally plain in v0.5. Visual media request UX enhancements belong to the next v0.5 slice after auth foundation is merged.

## 7. Configuration

Add config under `auth`:

```yaml
auth:
  session_cookie_name: echo_session
  session_ttl_seconds: 604800
  session_touch_interval_seconds: 300
  secure_cookies: auto
```

Rules:

- `secure_cookies=auto` sets Secure when `r.TLS != nil` or `X-Forwarded-Proto: https` is trusted by deployment config.
- For the initial implementation, trust `X-Forwarded-Proto` only when a new `server.trust_proxy_headers` boolean is true. Default false.
- Cookie SameSite is `Lax`; Path is `/`; HttpOnly is always true.

## 8. Security Invariants

- No default browser password exists.
- Bootstrap token can set admin password but cannot authenticate normal routes.
- Password hashes and session secrets are never logged or returned.
- Login failure messages do not reveal whether username or password was wrong.
- Session cookie is HttpOnly and SameSite=Lax.
- Session-auth mutations require CSRF.
- Bearer-auth compatibility remains exact: existing API token requests continue to work without CSRF.
- Public `/healthz`, `/readyz`, `/metrics`, `/static/*` behavior remains unchanged.
- Emby proxy routes remain outside browser session auth and keep their own playback-token boundary.
- `/api/discovery/*` and `/ui/discovery/*` stay admin-only.
- `/api/me/discovery/*` and `/app/*` stay discovery-scope user surfaces.

## 9. Error Handling

- Login bad credentials: `401 {"error":"unauthorized"}`.
- Login disabled user: same 401.
- Missing password hash: same 401.
- Malformed JSON: 400.
- CSRF failure: 403 `csrf-token-required` or `csrf-token-invalid`.
- Expired session: 401 and clear cookie where possible.
- Store failure: 500 with generic `internal-error`, detailed server log with redaction.

## 10. Testing

Unit and handler coverage:

- Password hash encode/verify accepts correct password and rejects wrong password.
- Malformed password hash fails closed.
- Bootstrap admin password requires bootstrap Bearer token.
- Login rejects unknown, disabled, passwordless, and wrong-password users with same status.
- Login creates session, sets cookie attributes, returns CSRF token.
- `/api/session/me` returns redacted user projection and no password/token hashes.
- Logout revokes only current session and clears cookie.
- Expired and revoked sessions reject.
- Bearer auth still passes without CSRF.
- Session-auth POST without CSRF fails.
- Session-auth POST with CSRF succeeds.
- Admin shell no longer renders token input.
- App shell no longer renders token input.
- Admin/user scope isolation remains unchanged for `/ui/*`, `/api/discovery/*`, `/app/*`, and `/api/me/discovery/*`.

Integration gate:

- Bootstrap admin password.
- Login as admin.
- Create or verify a user with discovery scope through existing test helper path.
- Login as user.
- Load `/app`, search TMDB through fake service, create media request with CSRF.
- Confirm the same flow fails without CSRF.
- Confirm an existing Bearer API token can still create the same request without CSRF.

Standard verification:

```bash
go test ./... -count=1
make migrate
make build
```
