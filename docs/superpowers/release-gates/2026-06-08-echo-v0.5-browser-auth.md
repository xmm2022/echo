# Echo v0.5 Browser Auth Gate

Date: 2026-06-08

## Scope

This gate covers the v0.5 browser auth foundation: bootstrap admin password, username/password login, web sessions, CSRF for cookie-auth mutations, browser shell token removal, and Bearer API token compatibility.

## Required Local Gates

- `go test ./... -count=1`
- `make migrate`
- `make build`
- `go test ./internal/http/... ./internal/web/... -run 'Test(Bootstrap(AdminPassword|CreatesAdminToken)|Session(LoginMeLogout|MeBearerHasNoCSRF)|ControlPlaneCSRFSkipsBearerAndRejectsSessionMutations|CSRFRequiresTokenForSessionMutationsOnly|AppJSSessionAuthGlue(Static|Runtime)|AppRoutesUsePublicShellAndAuthenticatedDiscoveryFragments|MountUIRequiresAdmin)' -count=1`
- `go test ./integration -run TestBrowserAuthFakeFullPath -count=1`

## Verification Notes

`go test ./integration -run TestBrowserAuthFakeFullPath -count=1` is the fake browser full-path gate for browser login/session, CSRF success and missing-token rejection, and media request creation. Bootstrap admin password and Bearer-token compatibility are verified by the focused internal HTTP/Web command above.

## Required Behavior

- Fresh DB admin cannot log in until `/api/bootstrap/admin-password` succeeds with the bootstrap token.
- Browser login sets an HttpOnly `echo_session` cookie.
- With a cookie-auth session, `/api/session/me` returns a redacted user projection and CSRF token.
- Cookie-auth POST without `X-CSRF-Token` returns 403.
- Cookie-auth POST with the current CSRF token succeeds.
- Bearer API token requests continue to work without CSRF.
- `/ui/discovery/*` and `/api/discovery/*` remain admin-only.
- `/app/*` and `/api/me/discovery/*` remain discovery-scope user surfaces.
