# Echo v0.4 Media Request Gate

## Local Fake Gate

Run:

```bash
go test ./integration -run 'TestMediaRequestFakeFullPathReusesOneDiscoverySubscription|TestDiscoveryFakeFullPathQueuesOneProducerJob' -count=1 -v
```

Expected: one canonical discovery subscription, two user subscriptions, one
producer job after match accept, no sensitive fields in user projections.

## Operator Gate

This is a manual gate against one running Echo deployment and one Echo database.
Do not use `TestDiscoveryRealTelegram115Gate` as a substitute for steps 1-3
below: that test creates its own temporary store and validates the v0.3 discovery
path, not the v0.4 user request admission path.

Required environment:

- `ECHO_REAL_DISCOVERY_GATE=1`
- existing v0.3 TMDB/115 discovery gate variables from
  `docs/superpowers/release-gates/echo-real-gates.env.example`
- `ECHO_BASE_URL`, for example `http://127.0.0.1:8080`
- `ECHO_DB`, the SQLite database used by that Echo process
- `ECHO_BOOTSTRAP_ADMIN_TOKEN`
- `ADMIN_TOKEN`, one DB-backed API token with `admin` scope
- `USER_ID` and `USER_TOKEN`, one active user API token with `discovery` scope
- `LIBRARY_ID`, `PRODUCER_PROFILE_ID`, and `RULE_PROFILE_ID` from the existing
  v0.3 discovery setup
- `TMDB_QUERY`, `TMDB_ID`, and `MEDIA_TYPE` for the title being requested

If an admin token does not already exist, mint one with the bootstrap token:

```bash
curl -sS -X POST "$ECHO_BASE_URL/api/bootstrap/admin-token" \
  -H "Authorization: Bearer $ECHO_BOOTSTRAP_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"v0.4-gate-admin"}' | tee admin-token.json

export ADMIN_TOKEN="$(jq -r '.token' admin-token.json)"
```

The current MVP does not expose a public user-token mint endpoint. For this gate,
prepare the user and `discovery` token in the controlled gate database:

```bash
export USER_ID="${USER_ID:-v04-gate-user}"
export USER_TOKEN="${USER_TOKEN:-v04-gate-user.$(openssl rand -base64 32 | tr -dc 'A-Za-z0-9_-')}"
export USER_TOKEN_HASH="sha256:$(printf '%s' "$USER_TOKEN" | sha256sum | awk '{print $1}')"
export NOW="$(date +%s)"

sqlite3 "$ECHO_DB" <<SQL
INSERT INTO users (id, username, role, status, quota_policy_id, created_at, updated_at)
VALUES ('$USER_ID', '$USER_ID', 'user', 'active', 1, $NOW, $NOW)
ON CONFLICT(id) DO UPDATE SET status='active', updated_at=$NOW;

INSERT INTO api_tokens (id, user_id, name, token_hash, scopes, created_at)
VALUES ('tok_v04_gate_user', '$USER_ID', 'v0.4 gate user', '$USER_TOKEN_HASH', '["discovery"]', $NOW)
ON CONFLICT(id) DO UPDATE SET token_hash='$USER_TOKEN_HASH', scopes='["discovery"]', revoked_at=NULL;
SQL
```

Create a request policy and target for the gate:

```bash
curl -sS -X POST "$ECHO_BASE_URL/api/discovery/access-policies" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"v0.4 gate approval","enabled":true,"priority":1000,"subject_user_id":"'"$USER_ID"'","request_mode":"approval_required","can_search":true}' \
  | tee policy.json

export POLICY_ID="$(jq -r '.id' policy.json)"

curl -sS -X POST "$ECHO_BASE_URL/api/discovery/access-policies/$POLICY_ID/targets" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"label":"v0.4 gate target","library_id":'"$LIBRARY_ID"',"producer_profile_id":'"$PRODUCER_PROFILE_ID"',"rule_profile_id":'"$RULE_PROFILE_ID"',"pipeline_owner_id":"admin","media_type":"'"$MEDIA_TYPE"'","match_mode":"admin_review","grant_playback_on_approval":true,"enabled":true,"default_target":true}' \
  | tee target.json

export TARGET_ID="$(jq -r '.id' target.json)"
```

Flow:

1. User searches TMDB through `/api/me/discovery/search`:

   ```bash
   curl -sS --get "$ECHO_BASE_URL/api/me/discovery/search" \
     --data-urlencode "q=$TMDB_QUERY" \
     --data-urlencode "type=$MEDIA_TYPE" \
     -H "Authorization: Bearer $USER_TOKEN" | tee search.json
   ```

2. User creates request through `/api/me/discovery/requests`:

   ```bash
   curl -sS -X POST "$ECHO_BASE_URL/api/me/discovery/requests" \
     -H "Authorization: Bearer $USER_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"tmdb_id":"'"$TMDB_ID"'","media_type":"'"$MEDIA_TYPE"'","target_id":'"$TARGET_ID"'}' \
     | tee request.json

   export REQUEST_ID="$(jq -r '.id' request.json)"
   ```

3. Admin approves through `/api/discovery/requests/{id}/approve`:

   ```bash
   curl -sS -X POST "$ECHO_BASE_URL/api/discovery/requests/$REQUEST_ID/approve" \
     -H "Authorization: Bearer $ADMIN_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"note":"v0.4 gate"}' | tee approve.json

   export SUBSCRIPTION_ID="$(jq -r '.subscription_id' approve.json)"
   ```

4. Run the existing v0.3 source crawl, subscription check, match review, and
   dispatch flow against `SUBSCRIPTION_ID` in the same deployment/database. Use
   the admin discovery UI/API or the existing operator gate procedure, but keep
   the approved v0.4-created canonical subscription as the subscription under
   test.

5. User reads `/api/me/discovery/subscriptions`:

   ```bash
   curl -sS "$ECHO_BASE_URL/api/me/discovery/subscriptions" \
     -H "Authorization: Bearer $USER_TOKEN" | tee subscriptions.json
   ```

Acceptance:

- In a clean gate DB, exactly one `discovery_subscriptions` row exists for
  `(tmdb_id, media_type, owner_id='admin', library_id)`. In a shared DB, record
  before/after counts and require one new canonical row at most.
- Exactly one `user_media_subscriptions` row exists for `USER_ID` and
  `SUBSCRIPTION_ID`.
- User request creation does not create an `ingest_producer` job.
- After match accept/dispatch, exactly one new `ingest_producer` job is linked to
  the reviewed match.
- `subscriptions.json`, `request.json`, logs, and operator notes do not include
  `share_code`, `receive_code`, `raw_text_ref`, `secret_ref`, `target_account`,
  `storage_mount`, `default_args_json`, `queued_job_id`, producer args, raw
  debug refs, storage mounts, account ids, or raw share URLs.

Quick JSON response check:

```bash
rg -n 'share_code|receive_code|raw_text_ref|secret_ref|target_account|storage_mount|default_args_json|queued_job_id|producer args|https://115\\.com/s/' \
  request.json approve.json subscriptions.json
```

Expected: no matches.
