# Echo v0.2 Real Emby Release Gate

## Environment

- Echo URL: `https://echo.example.com`
- Emby client server URL: `https://echo.example.com/emby`
- Echo config has `emby_proxy.enabled=true`
- Echo config has `emby_proxy.proxy_prefix=/emby`
- Echo has at least one enabled Emby user link
- Echo has at least one enabled library mapping
- Echo has at least one enabled account pool assignment for the mapped user

## Required Manual Checks

- [ ] PlaybackInfo for a mapped item returns only `/emby/stream/{token}` or `/emby/error/{token}` playable URLs.
- [ ] PlaybackInfo for a mapped item does not return `/api/restore`, `/api/stream`, upstream Emby stream URLs, upstream signed URLs, Authorization headers, Cookie headers, or X-Emby-Token values.
- [ ] Mapped media starts playback in a real Emby client.
- [ ] Seek works at least twice in the same playback session and byte quota follows actual bytes sent.
- [ ] Pause and resume keep the same user/session attribution.
- [ ] An unmapped item still plays through upstream Emby.
- [ ] Quota exhaustion returns a controlled client-facing error with `X-Echo-Reason: quota_exceeded`.
- [ ] Disabled account pool returns a controlled client-facing error with `X-Echo-Reason: account_unavailable` or `temporary_unavailable`.
- [ ] Confirmed dead copy falls back to another live copy before response headers are sent.
- [ ] Suspect `/d/` HTML failure does not permanently mark the copy dead.
- [ ] Existing subtitle metadata remains present in PlaybackInfo. Subtitle URL proxying is not required for v0.2; unsafe mapped playable subtitle URLs fail closed.
