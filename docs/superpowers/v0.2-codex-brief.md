## v0.2 目标(spec §11 路线)

Rose-like / NextEmby-like 媒体代理层,建在 v0.1 资源池之上,消费 v0.1 manifest + restore/stream,与 v0.1 核心**松耦合**:

- **Emby 反代 + PlaybackInfo 改写**:拦截 Emby 播放请求,把媒体直链/流替换为 echo 的 `/api/restore/{file_id}` 或 `/api/stream/{file_id}`,让 `.echo` 占位在 Emby 里可播。
- **多用户 + Cookie 池**(v0.1 是单 admin token)。
- **per-user 配额追踪**。

## 硬约束(不要推翻)

- **松耦合**:v0.2 是消费 v0.1(manifest + restore/stream API + DB 模型)的应用层,**不重写** v0.1 核心模块(store/ingest/sidecarclient/castree)。
- **防回头墙**:spec §12 + plan §16(R1 8 条 + R2 9 条)是 v0.1 已拍板/已否决决策,设计 v0.2 时**不要回头改**;要挑战先指认理由。
- **技术栈沿用**:Go 1.22 / chi / sqlc / SQLite(→PG 可选) / templ+htmx / log/slog / AGPLv3。
- **进程边界**:echo 不通过 Go module import sidecar,HTTP REST 边界。

## 两个 v0.1 遗留前置(v0.2 实现开工前必须先清,设计时纳入排期)

1. **块2 真机自动化回归**:`integration/real_115_test.go` 连真机端到端跑通(需真机 sidecar token + 外部 cas-pipeline 产的小样本 `.cas tree`)。
2. **Phase 7 sidecar 错误模型对齐**(详见 spec §5"Phase 12 实测: sidecar 错误模型"):实测发现 openlist admin/fs API 失败 = **HTTP 200 + body code**、`/d/` = **HTTP 500 + HTML**,**没有 404/410 这种 dead 信号**,导致 echo `handleCopyFailure` 的 `MarkDead` 真机永不触发(失效副本反复重试;fallback 兜底仍工作故 v0.1 非阻塞)。**但 v0.2 是 Emby 反代,多副本 fallback + 坏副本剔除是播放体验核心**——v0.2 设计必须把"sidecar 错误模型对齐 + 坏副本 dead 策略(含连续失败计数等启发式)"作为**早期/前置任务**,并设计真机各失败场景(文件不存在 / storage 失效 / 账号挂)的探测与分类。
